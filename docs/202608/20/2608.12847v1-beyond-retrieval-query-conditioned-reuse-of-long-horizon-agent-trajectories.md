## 摘要
检索可以识别出可能重要的历史轨迹，但它并未说明在用户、实体、约束或环境状态发生变化后，行动中的智能体应如何使用该轨迹。我们将这种检索后复用步骤识别为长时程轨迹记忆的一个独立瓶颈，并构建了一个评估框架，该框架在保持候选检索、目标状态、模型、解码和工具预算固定的同时，改变提供给智能体的支持。我们用查询条件复用（QCR）实例化该框架，这是一种刻意简单的目标绑定笔记，记录了可复用的过程、需要恢复的绑定、适用条件和验证要求。QCR用于检验复用假设，而非主张一种普遍偏好的记忆格式。在WebArena、WorkArena和AppWorld中的2,391个目标实例上，QCR达到了62.3%的平均成功率，比完整轨迹高出10.7个百分点，同时使用的在线令牌减少了48.9%。摘要重排序为94.8%的目标选择了可复用的记忆，使最终任务成功率与理想可复用选择器的差距在1.8个百分点以内。通过轨迹长度和源-目标绑定转移的分析表明，随着轨迹变长或源特定值发生变化，直接轨迹注入会损失大部分效用，而目标绑定支持则保留了测量增益中较大的一部分。所得框架将检索质量与将检索到的经验转化为安全、有用的新任务支持这一过程分离开来。

## Abstract
Retrieval can identify a past trajectory that may matter, yet it does not specify how an acting agent should use that trajectory after users, entities, constraints, or environment state have changed. We identify this post-retrieval reuse step as a distinct bottleneck for long-horizon trajectory memory and formulate an evaluation framework that holds candidate retrieval, target state, model, decoding, and tool budget fixed while varying the support delivered to the agent. We instantiate the framework with query-conditioned reuse (QCR), a deliberately simple target-bound note that records a reusable procedure, bindings to recover, applicability conditions, and verification requirements. QCR serves to test the reuse hypothesis rather than to claim a universally preferred memory format. Across 2,391 target instances in WebArena, WorkArena, and AppWorld, QCR reaches 62.3% average Success, 10.7 points above Full Trajectory, while using 48.9% fewer online tokens. Summary reranking selects a reusable memory for 94.8% of targets, placing end-task Success within 1.8 points of an oracle reusable selector. Analyses by trajectory length and source--target binding shift show that direct trajectory injection loses much of its utility as traces grow longer or source-specific values change, whereas target-bound support preserves a larger share of the measured gain. The resulting framework separates retrieval quality from the problem of turning retrieved experience into safe, useful support for a new task.

### 1. 核心问题与研究动机

- **背景**：智能体记忆系统已从短期交互历史发展到外部存储、结构化记录、检索索引和可学习的记忆操作，相关评测（如 LongBench、LongMemEval 等）大多聚焦于"能否存取"——即能否保留、排序并回答关于历史交互的问题。
- **核心矛盾**：能够"取回"历史不等于"会用"历史。对于短事实或自包含的小记忆片段，检索到相关知识往往与完成当前任务几乎等价；但对于长时程任务轨迹，轨迹中同时包含可迁移的工作流、决策规则，以及大量已过期的源特定绑定（如用户名、文件路径、日期、对象 ID、环境状态等）。检索到轨迹后，智能体仍须判断哪些部分仍适用、哪些绑定已失效、哪些检查必须重做。
- **核心问题**：论文明确指出"检索后复用"（post-retrieval reuse）是长时程轨迹记忆的独立瓶颈，并主张记忆评估应转向"历史经验是否真正改善了当前查询的求解"——即更高的验证完成率、更少的无效探索、更低的在线成本。
- **总体含义**：需要将"检索质量"与"将检索到的经验转化为当前任务的有效支持"这两个问题分开评估。论文提出了一种新的评估框架和一种名为"查询条件复用"（QCR）的最小实现，用以验证这一瓶颈假说。

### 2. 方法论

#### 2.1 核心思想

- **问题形式化**：对于目标任务 \(t\)（查询 \(q_t\)、初始观测 \(o_{t,0}\)），固定的检索器 \(R\) 从冻结的轨迹库 \(B\) 返回相同的 top-k 候选集 \(Z_t\)；一种复用机制 \(\rho\) 将 \(Z_t\)、\(q_t\)、\(o_{t,0}\) 转化为支持对象 \(r_t\)；行动智能体基于 \((q_t, o_{t,0}, r_t)\) 生成新轨迹 \(\hat{\tau}_t\)，并由目标环境自身的验证器判定结果。
- **评估边界**：保持候选检索结果、目标状态、模型、解码配置、工具预算固定，仅改变"选中的同一条历史轨迹被如何表示和使用"，从而将差异精确归因于复用环节。

#### 2.2 离线记忆库构建

- 统一冻结记忆库：由 WebArena、WorkArena、AppWorld 三个环境中的 623 条验证成功的源任务轨迹构成，跨环境混合索引，不按环境分区。
- 每条记录包含源指令、有序观测与动作序列、工具调用及返回结果、终端工件、验证器结果；环境标签、任务 ID 等溯源信息不进入检索表示和目标提示。
- 从难度适中的任务族中构建（既非平凡任务，也非无成功记录的任务），使历史经验存在发挥作用的空间。

#### 2.3 绑定感知的目标构造

- 每条源轨迹生成最多 4 个目标变体，保留源任务的工作流意图，同时替换一个或多个目标特定绑定（实体、用户、记录 ID、文件/位置、日期、参数或初始状态）。
- 变体按绑定变化程度分为：无重写、小（1 个局部绑定）、中（2-3 个绑定或一个核心约束）、大（至少 4 个绑定，或同时改变目标实体和初始环境状态）。
- 源-目标配对关系仅作为密封审计元数据保留，不进入检索索引、提示或目标输入。
- 最终得到 2,391 个有效目标实例（平均每个历史轨迹 3.84 个变体）。

#### 2.4 查询条件复用（QCR）支持笔记

QCR 生成一个简短的目标绑定支持对象，包含四个字段（刻意保持最小化设计，不声称是通用最佳记忆格式）：

| 字段 | 内容 | 目标侧要求 |
|---|---|---|
| 工作流不变式 | 保留工具顺序、决策规则和先验验证步骤 | 仅保留适用于目标的动作模式 |
| 待恢复绑定 | 实体、路径、日期、用户、记录 ID、参数 | 从当前证据恢复值，不复制源绑定 |
| 适用条件 | 源前提条件、约束和分支条件 | 前提不成立时拒绝复用 |
| 验证护栏 | 源中用于判定完成状态的检查 | 必须在目标侧确认结果后再完成 |

#### 2.5 信息边界与执行流程

- QCR 写入器只能读取选中的轨迹、目标查询和初始目标观测；不能私下调用环境、替换缓存选择或查看隐藏评估信息。
- 历史信息在提示中明确为"参考性"而非"字面重放指令"。
- 在线 token 成本计算包括：基础行动提示 + 传输记忆 + 支持合成输入/输出 + 行动输出；源轨迹构建成本归入离线日志。

### 6. 主要结论

#### 6.1 端到端性能

- QCR 平均成功率达 **62.3%**，比 Full Trajectory（51.6%）高 **10.7 个百分点**，比 Generic Summary 高 7.2 点，比 No Memory 高 23.9 点。
- 效率优势显著：QCR 平均 16.7 次 API 调用、9.4k 在线 tokens，比 Full Trajectory（21.9 次、18.4k）节省 **48.9% 的在线 token**，且非以牺牲成功率为代价。
- 三个环境中的排序一致：QCR 在所有 6 个环境-指标的对比中均最优。

#### 6.2 检索 vs 复用

- 检索问题基本已被解决：top-5 候选覆盖配对轨迹 95.6%、可复用轨迹 97.8%；重排后最终可复用记忆准确率达 **94.8%**，端任务成功率距 oracle 可复用选择仅差 **1.8 个百分点**。
- 剩余的主要损失发生在"候选已选中"之后——即复用环节。

#### 6.3 轨迹长度与绑定变化的影响

- 直接注入随轨迹变长急剧退化：Full Trajectory 的效用从短组的 +18.4 降至超长组的 **+2.9**（保留 15.8%）；QCR 在超长组仍保持 **+13.2**（保留 60.3%）。
- 绑定变化越大，直接注入越差：大改写下 Full Trajectory 效用仅为 **+2.2**（保留 8.2%），QCR 仍达 **+20.1**（保留 67.9%）。
- 大改写下 Full Trajectory 产生陈旧绑定错误率 46.9%，QCR 仅为 10.9%；正确重绑定率从 31.7% 升至 77.8%。

### 7. 方法亮点

1. **问题定义清晰**：将"检索"与"复用"明确分离，并设计了严密的信息边界——彻底排除 oracle 源轨迹泄漏、环境标签泄漏和验证器信息泄漏。
2. **评估框架可复现**：固定候选集、选中轨迹、模型、解码、工具预算的"受控对比"协议，使不同记忆表示方式的差异可被精确归因。
3. **最小化干预设计**：QCR 的四个字段刻意简洁，不引入复杂的图结构或学习记忆策略，从而能够干净地验证"复用是瓶颈"的核心假说。
4. **跨环境统一记忆库**：打破环境边界，让智能体能在不同环境之间迁移程序知识，更接近真实部署场景。
5. **绑定感知的目标构造**：通过系统性的绑定变化（从无到大规模）制造可控的"源-目标差距"，使复用困难可量化和可分析。
6. **成本透明度**：完整记录 token 分解（基础提示、记忆传输、支持合成、行动输出），不将支持生成成本隐藏在降低的行动输出之下。

### 8. 不足与局限性

1. **实验覆盖范围有限**：仅评估成功源轨迹、单条选中记忆、受控绑定转移；未覆盖自然发生的任务历史、部分失败轨迹、多记忆组合或开放式记忆获取。
2. **受控场景与现实存在偏差**：绑定感知重写是人工构造的，真实部署中的源-目标差异模式可能更复杂、更隐蔽。
3. **安全性未充分评估**：只测验证完成率，未测量不可逆副作用、策略违规或复用轨迹带来的安全风险；token 节省不应被解读为所有任务都应减少 token（安全敏感任务可能需更多检查）。
4. **因果推断受限**：长度和绑定变化分析中的效用差异与任务难度混淆，论文承认这是"关联而非因果"。
5. **无法拆解各字段贡献**：QCR 四个字段的整体效果已验证，但未分别消融每个字段的独立作用。
6. **单模型结果**：全部实验使用 DeepSeek-V4-Pro，未验证不同模型规模或训练分布的鲁棒性。
7. **候选选择仍有提升空间**：重排后仍有 5.2% 的选中记忆不相关，端任务成功率距 oracle 选择差 1.8 点，选择环节并非已完全解决。

### 结语

该论文最重要的贡献在于**重新定义了智能体记忆评估的问题边界**：存储和检索之外，"复用"是一个独立的、随记忆长度增长而愈发关键的瓶颈。QCR 作为最小实现证明了这一假说——在相同检索结果的条件下，目标绑定的支持表示显著优于原始轨迹直接注入，且成本更低。该框架为未来记忆系统的设计与评估提供了一个清晰的、可扩展的协议，但也留下了关于多记忆组合、学习型复用策略、安全性保障和更广泛部署场景的开放问题。
