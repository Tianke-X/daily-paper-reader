## 摘要
基于图的检索增强生成（GraphRAG）在结构化语料库图上检索多跳问题的证据。现有的GraphRAG方法在证据发现与来源锚定之间的联系上不够明确。我们提出了LineageRAG，它为每个查询衍生的证据需求构建一条证据谱系，并在所选证据支持该需求时，用逐字的来源片段完成该谱系。LineageRAG首先初始化证据需求，然后通过基于需求的条件检索在语料库图上扩展每个谱系，同时保留每个候选证据关联的需求。谱系完成利用这种溯源信息来选择互补的段落，并将受支持的需求锚定在逐字的来源文本中。在HotpotQA、2WikiMultiHopQA和MuSiQue上的实验表明，与领先的GraphRAG基线相比，LineageRAG在R@5、EM和F1上平均提高了3.51、5.96和5.22个百分点。

## Abstract
Graph-based Retrieval-Augmented Generation (GraphRAG) retrieves evidence for multi-hop questions over structured cor- pus graphs. Existing GraphRAG methods leave the connection between evidence discovery and source grounding implicit. We propose LineageRAG, which constructs one evidence lin- eage for each query-derived evidence demand and completes it with a verbatim source span when the selected evidence supports that demand. LineageRAG first initializes the evi- dence demands. It then expands each lineage through demand- conditioned retrieval over the corpus graph while retaining the demand associated with every candidate. Lineage completion uses this provenance to select complementary passages and grounds supported demands in verbatim source text. Experi- ments on HotpotQA, 2WikiMultiHopQA, and MuSiQue show that LineageRAG improves R@5, EM, and F1 by 3.51, 5.96, and 5.22 points on average over leading GraphRAG baselines.

## 1. 论文的核心问题与整体含义

- **研究动机**：多跳问答（multi-hop QA）需要从外部语料中检索并组合多条证据，传统 RAG 对单跳问题有效，但对需要桥接证据的多跳问题表现不足。GraphRAG 通过结构化语料图进行检索，能缓解这一问题，但现有 GraphRAG 方法在“证据发现”与“来源锚定（source grounding）”之间缺乏显式关联：模型检索到了候选段落，却没有记录“每个段落是为了回答哪个中间证据需求（Evidence Demand）而出现的”。
- **核心问题**：如何让 GraphRAG 在检索过程中携带每一个证据需求的身份，并从图谱发现一路贯穿到最终的逐字来源证据？
- **整体含义**：论文提出 **LineageRAG**，为每个查询衍生的证据需求构建一条“证据谱系（evidence lineage）”，并最终用原文中的逐字片段（verbatim span）补全该谱系。这样既提高了多跳证据的覆盖完整性，也让最终证据具有可追溯性，从而提升检索与问答质量。

## 2. 论文提出的方法论

### 核心思想

- 借鉴生物学中的谱系追踪与数据库中的“数据血缘”概念，将“证据需求 → 候选段落 → 最终来源片段”的完整追溯链路定义为 **evidence lineage（证据谱系）**。
- 每个查询被分解为有序的 **Evidence Demands**（证据需求），每个需求指明“证据必须确立的事实”。
- 检索和选择过程中始终保留每条候选段落与证据需求的关联（demand–passage provenance）；最终从选中段落中抽取逐字 span，并将 span 与对应需求绑定，完成谱系锚定。

### 三阶段流程

1. **Evidence-Demand Induction（证据需求归纳）**
   - 使用推理时 LLM（Qwen3-32B），通过固定 prompt \(P_D\) 将查询 \(q\) 分解为最多 5 个有序证据需求：
     \[
     R_q = (r_1,\dots,r_m),\quad r_j = (id_j,\delta_j,I_j,O_j)
     \]
   - \(\delta_j\)：该需求要求证据确立的事实描述；\(I_j\)：该需求消费的符号变量；\(O_j\)：该需求应产出的符号变量。
   - 需求 ID 在后续检索、选择、锚定阶段保持不变。

2. **Demand-Conditioned Lineage Expansion（需求条件谱系扩展）**
   - 对每个证据需求 \(r_j\)，在图索引 \(G\) 上独立执行检索：
     \[
     L_j = \text{Retrieve}_G(q,\delta_j) = (d_{j,1},\dots,d_{j,h})
     \]
   - 检索采用 HippoRAG 2 的 Personalized PageRank（PPR），但种子由 \((q,\delta_j)\) 共同决定，不把先前需求解析出的值代入后续检索。
   - 所有 list 按需求顺序合并为候选池 \(C_q\)，并保留每个候选的 provenance：
     \[
     A_q(d) = \{(id_j,\ell) \mid d = d_{j,\ell}\}
     \]
     - 同时记录被重复暴露的次数 \(n_q(d)\)、最好排名 \(\rho_q(d)\)、同标题冗余度 \(g_q(d)\)。

3. **Lineage Completion with Source Grounding（谱系完成与来源锚定）**
   - **Set-wise selection**：直接用 LLM 对候选池进行集合式选择（而非逐条排序），输入每个候选的 provenance 信息，指示模型优先选择能覆盖尚未被满足的需求的互补段落，最终选出 \(k\) 个段落 \(S_k\)。
   - **Source grounding**：从选中段落中抽取“与需求对应的逐字片段”，形成注释：
     \[
     w = (i_w,d_w,s_w,a_w)
     \]
     表示需求 \(i_w\) 被段落 \(d_w\) 中的 span \(s_w\) 支持，\(a_w\) 为类型化关系。
   - 过滤条件 \(Valid_q(w)\)：
     - span 确实在所选段落中；
     - schema 合法；
     - 存在 provenance 记录 \((i_w,\ell)\in A_q(d_w)\)，即需求与段落确实有追溯关联；
     - 去除重复的段落–span 对。
   - 最终 reader 接收段落 \(S_k\) 和锚定注释 \(W_q\)，注记中未覆盖的需求对应的谱系保持“开放”。

### 形式化输出

\[
O_q = (S_k, W_q), \quad S_k = (d^{(1)},\dots,d^{(k)}) \in D^k
\]

其中 \(S_k\) 是有序且互不重复的段落列表，\(W_q\) 是带来源锚定的注释集合。

## 6. 论文的主要结论与发现

- LineageRAG 在三个多跳 QA 基准上取得最优平均结果：R@5 = 89.57，EM = 58.22，F1 = 69.63。
- 相对于最强 GraphRAG 基线，平均提升：R@5 +3.51，EM +5.96，F1 +5.22。
- 在 2WikiMultiHopQA 上，LineageRAG 的 R@5 领先最多（94.03），且在 EM/F1 上接近或大幅领先多数基线；相对 HippoRAG 2 的 F1 提升达 8.68 点。
- 消融显示：
  - 去掉 Evidence-Demand Induction：R@5 -0.92，EM -1.84，F1 -1.20；
  - 去掉 Lineage Expansion：R@5 -2.15，EM -1.58，F1 -1.28（对检索影响最大）；
  - 去掉 Source Grounding：R@5 不变，但 EM -6.20，F1 -5.65（对 reader 使用证据影响最大）。
- 机制分析表明：
  - set-wise selection 本身贡献 1.30 R@5；正确保留 demand–passage provenance 额外贡献 2.19 R@5；
  - 错误的 provenance 会显著伤害选择（R@5 降至 68.42），信息缺失时影响较小（73.58）；
  - Source Grounding 在 1,865/2,182 条证据需求上完成谱系，420/500 条审计 span 提供完全支持，10/500 条存在需求–span 错配；
  - 在段落集合和顺序完全相同的情况下，仅增加 grounded spans 使 EM 提升 6.20、F1 提升 5.65，证明来源锚定主要改善答案生成阶段的证据利用效率。

## 7. 优点

- **问题定义清晰**：将 GraphRAG 中“证据发现”和“来源锚定”的隐式关系显式化为“证据谱系”，概念新颖且有启发性。
- **端到端可追溯**：从需求归纳、检索、选择到最终 span 锚定，全程保留需求 ID，形成完整的血缘链路，增加了可解释性。
- **检索与选择协同设计**：provenance 同时用于文档选择和后续 grounding，不是事后附加模块，而是流程的核心信息载体。
- **实验设计科学**：
  - 与 HippoRAG 2 共享图索引和检索设置，保证对照公平；
  - 通过“候选池 oracle + selected R@5”分离“候选暴露”和“选择损失”；
  - 对 provenance 进行“移除 / 中性替换 / 洗牌”的精细扰动控制，能直接归因正确 provenance 的作用；
  - 固定段落集合、仅改变是否提供 grounded spans，实现了对 reader 增益的干净隔离。
- **成本可控**：查询时仅增加约 880 tokens/query，换来显著收益，开销可接受。

## 8. 不足与局限

- **数据集覆盖有限**：只在三个多跳 QA 数据集上验证，未涉及更丰富场景（如医学、法律、金融等知识密集型领域），泛化性待验证；每条数据仅用 1,000 条查询，不是完整测试集。

- **计算成本报告不完整**：只有 token 数，缺少 GPU 型号、训练/推理时间等具体算力指标。
