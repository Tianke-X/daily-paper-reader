## 摘要
大型语言模型处理大量信息，但通常缺乏维护紧凑且不断演化的概念表示的显式机制。我们引入了心智模型管理（3M），这是一种将知识表示为由紧凑块组成的心智模型的框架。3M不是积累文本段落，而是将新信息持续整合到现有的概念表示中。一组操作符提取知识、检索相关模型、添加和更新块、重组表示、检测不一致性并推导新知识。我们描述了3M的主要操作符，并使用进化策略作为贯穿示例来说明每个操作。

## Abstract
Large language models process large amounts of information but usually lack an explicit mechanism for maintaining compact and evolving conceptual representations. We introduce Mental Model Management (3M), a framework in which knowledge is represented as mental models consisting of compact chunks. Rather than accumulating text passages, 3M continuously integrates new information into an existing conceptual representation. A set of operators extracts knowledge, retrieves relevant models, adds and updates chunks, reorganizes representations, detects inconsistencies, and derives new knowledge. We describe the main 3M operators and illustrate each operation using Evolution Strategies as a running example.

### 二、方法论

#### 2.1 核心思想

- **心智模型（Mental Model, M）**：与某概念关联的一组紧凑知识块（chunks）的集合，`M = {c1, c2, ..., ck}`。每个 chunk 可编码事实、关系、规则、观察、程序、假设或推导原则。
- **3M记忆**：心智模型的集合 `M = {M1, M2, ..., Mn}`。
- **与文本摘要的本质区别**：摘要是对单一文档的压缩，而心智模型整合跨文档、跨交互的概念性信息，持久存在且各块可独立变化。
- **处理原则**：新信息"不直接追加"，而是通过算子决定是否扩展、更新、合并、压缩或修正现有模型。

#### 2.2 算子体系（Operator Vocabulary）

算子按功能分为三类：

| 类别 | 算子 |
|------|------|
| **知识获取** | Extract（提取）、Retrieve（检索） |
| **记忆管理** | Add（添加）、Update（更新）、Merge（合并）、Split（拆分）、Connect（连接）、Compress（压缩）、Prune（剪枝） |
| **认知处理** | Conflict Detection（冲突检测）、Conflict Repair（冲突修复）、Generalize（泛化）、Specialize（特化）、Abstract（抽象化）、Infer（推断）、Analogy（类比）、Find Gap（发现知识缺口）、Verify（验证） |

#### 2.3 算法流程（以知识摄入为例）

外循环控制流：

```
T ——Extract→ C ——Retrieve→ MC ——o1,...,ok→ M̃ ——Verify→ M′
```

- **T**：输入文本
- **C**：瞬态概念与主张集合
- **MC**：检索得到的记忆子集
- **M̃**：暂存状态
- **M′**：提交后的持久状态
- 每个 `oi` 是从3M算子词汇表中选出的算子，k 可为0（无需持久变更）

**关键算子举例：**
- **Add**：以"语义新颖性"为前提，仅当信息未包含于现有块时添加，避免冗余；
- **Merge/Split**：在"模型级"合并等价概念模型或拆分过度宽泛的模型；
- **Compress**：将多个块概括为更小的表示，而非简单删除；
- **Conflict Repair**：通过区分不同条件/上下文将矛盾转化为统一表征（如区分"探索"与"优化性能"）；
- **Infer**：从多个现有块推导出新知识，并保留可追溯性；
- **Abstract**：在概念层级上构建更高级模型，不替代原模型；
- **Verify**：验证块是否得到支持及表述是否精确，尤其针对认知算子产出的派生知识。

### 三、实验设计

#### 3.1 实现环境

- 单一 Python 进程，**无第三方运行时依赖**；

- 运行于 **NVIDIA Spark** 硬件，使用 **qwen3.6** 模型，温度为 **0**；
- 每个3M算子使用独立提示词，控制器决定当前输入所需的算子；
- 持久知识仅存储为 **Markdown** 文件；JSON 仅用于瞬态控制器与算子响应。

- **输入**：1,577词的进化策略（Evolution Strategies）引言，导入**空记忆目录**；

- 总长度1,060词，为输入的**67.2%**，平均文件长度353.3词（范围260–471）；
- 存储了**24个显式关系**和**4个知识缺口**；
- 所有内容均由本地 qwen3.6 模型生成，无人工编辑。

#### 3.3 行为评估（Behavioral Evaluation）

- 构造**6个行为测试用例**，每个用例有**确定性评价标准**；

- 每个用例指定：预期算子、文件数上界、必需章节/术语、验证状态、冗余上界；

### 六、主要结论与发现

1. **3M框架可行**：通过最小化Markdown实现，证明算子能产生**可观察的不同记忆转化**——冗余输入不改变记忆，冲突触发显式检测与修复，前提触发推断，多个专门模型触发抽象。
2. **概念中心优于段落中心**：将知识组织为概念中心的心智模型，可将1,577词输入转化为1,060词的结构化、互联表示，且包含显式关系与知识缺口。
3. **处理更多信息≠积累更多文本**：通过更新、合并、压缩、剪枝等算子，可以在增加知识内涵的同时控制记忆规模。
4. **认知算子可产生派生知识**：推断、抽象、类比、泛化等算子使LLM能够超越输入文本，产生新的、可追溯的知识表述。
5. **算子对应可验证的行为差异**：行为评估表明，每个算子对应持久表示中**可观察的不同转化**，而非仅描述性标签。
6. **3M与RAG互补**：RAG决定哪些外部信息可用，3M决定信息如何改变持久概念记忆。

5. **与认知科学和信念修正理论衔接**：引入心理模型理论与信念修正逻辑（AGM），为LLM记忆管理提供理论锚点；

### 八、不足与局限

1. **实验覆盖有限**：仅一个技术领域（进化策略）、一个模型（qwen3.6），未验证跨领域、跨模型的泛化能力；
2. **统计效力不足**：每个测试用例仅运行一次，无重复实验、无置信区间，无法进行有效统计推断；
3. **验证可靠性问题**：验证算子和生成算子使用同一模型，**缺乏独立验证者**，存在自我确认偏差风险；
4. **规模瓶颈未检验**：未测试大量心智模型、长期累积记忆时的检索效率和表现，作者也承认需要嵌入、索引或图检索的扩展；
5. **无外部基准对比**：未与MemGPT、A-MEM等现有记忆系统进行定量对比，无法衡量在标准任务上的相对优劣；
6. **Jaccard冗余度量粗糙**：token级重叠不能充分代表语义冗余，可能高估或低估真实冗余；
7. **算子选择依赖LLM**：控制器策略依赖底层LLM的判断，算子选择、语义比较、推断均可能出错；
8. **理论承诺与实际落地差距**：3M本质依赖LLM的推理能力，认知算子（如泛化、类比）质量完全取决于底层模型能力，框架本身不提供正确性保证；
9. **未讨论多智能体或并发访问**：在代理系统多用户或并发场景下，心智模型的并发修改与一致性维护问题未涉及；
10. **计算成本未评估**：通过多次LLM调用（每个算子独立提示词）实现知识处理，整体开销与效率未量化。
