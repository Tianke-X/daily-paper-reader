## 摘要
虽然大型语言模型（LLM）智能体越来越依赖长期记忆进行持久交互，但管理这种记忆的检索机制很少被视为可演化的组件。这种静态方法限制了在异构记忆查询上的性能，这些查询通常需要多样化的证据构建策略。为了解决这个问题，我们引入了\textbf{ERSkill}，一个以检索为中心、用于自演化、技能引导的记忆访问框架。ERSkill将交互历史编译为结构化的记忆存储，并将检索行为表示为由基本原语组成的可执行技能。在推理时，训练好的路由器动态地将每个查询匹配到最优技能，以构建量身定制的证据用于答案生成。为了实现持续改进，ERSkill在训练期间共同演化技能集和路由器。它采用经验字典树来高效记录已探索的检索路径，并采用双边界机制，将新技能能力的扩展与稳定的、面向路由器的部署安全解耦。在多个智能体记忆基准上的实验表明，ERSkill大幅优于强大的非演化和自演化基线。值得注意的是，在使用Qwen3-Next-80B-A3B-Instruct时，它在F1、BLEU-1和LLM评判得分上的总体平均值提高了31.3%，在使用GPT-5.4-nano时提高了28.1%。

## Abstract
While Large Language Model (LLM) agents increasingly rely on long-term memory for persistent interactions, the retrieval mechanisms governing this memory are rarely treated as evolvable components. This static approach limits performance on heterogeneous memory queries, which often demand diverse evidence construction strategies. To address this, we introduce \textbf{ERSkill}, a retrieval-centric framework for self-evolving, skill-guided memory access. ERSkill compiles interaction histories into a structured memory store and represents retrieval behaviors as executable skills composed of fundamental primitives. At inference time, a trained router dynamically matches each query to the optimal skill to construct tailored evidence for answer generation. To enable continuous improvement, ERSkill co-evolves the skill set and the router during training. It employs an experience trie to efficiently record explored retrieval paths, alongside a double-frontier mechanism that safely decouples the expansion of new skill capabilities from stable, router-facing deployment. Experiments across multiple agent memory benchmarks demonstrate that ERSkill substantially outperforms strong non-evolving and self-evolving baselines. Notably, it improves the overall average across F1, BLEU-1, and LLM-judge scores by 31.3\% with Qwen3-Next-80B-A3B-Instruct and by 28.1\% with GPT-5.4-nano.

## 1. 核心问题与研究动机

- **研究背景**：LLM（大型语言模型）智能体正从一次性问答助手向能够持续数周乃至数月交互的持久协作伙伴演进。在长程交互中，智能体需要积累用户偏好、跟踪动态事件、记住历史决策并复用过往经验，因此"智能体记忆"成为关键研究主题。
- **现有工作的不足**：
  - 早期工作聚焦于外部记忆的**构建与维护**（信息抽取、压缩、更新、遗忘），如 A-Mem、MemoryOS、LightMem。
  - 近年自演化方法（如 ReasoningBank、MemSkill）虽能让智能体从过往轨迹中蒸馏可复用的推理经验或记忆构建技能，但**查询时的检索行为本身仍是预定义的静态策略**，例如 MemSkill 演化的是记忆抽取技能，而记忆访问仍用固定的稠密检索。
  - 这一静态设定在**异构记忆查询**场景下成为瓶颈：例如"Alice 在夏威夷旅行时为 Bob 买了什么礼物？"需要检索特定事件，而"为什么 Alice 后来不再计划和 Bob 再去夏威夷？"需要串联早期事件与后续发展、挖掘因果关系——二者需要性质不同的证据构建策略。
- **核心研究问题**：如何让 LLM 智能体演化并学会组合复杂的检索动作，使检索行为能够适应不同查询的异构信息需求？

## 2. 方法论：ERSkill 框架

### 2.1 总体思想
ERSkill 是一个**以检索为中心（retrieval-centric）的自演化框架**，将记忆访问建模为"技能引导的证据构建"。其核心思路是：把检索行为抽象为可执行、可复用、可解释的"技能"，并通过训练路由器为新查询动态匹配最优技能。

### 2.2 记忆存储与检索原语
- **结构化记忆**：将交互历史 D 编译为 M(D) = (A, I, G)：
  - **A**：原子级记忆记录集合（原子文本 + 元数据 + 时间戳 + 实体集）
  - **I**：索引集合（稠密检索的嵌入索引、实体到原子的倒排索引等）
  - **G**：图集合（相似度图、带类型的语义关系图，关系标签包括 Changed / Cause / Reason / HinderedBy / React / Want / none）
- **原语库（固定不变）**：包括搜索类（entity_search、lexical_search/BM25、dense_search）、扩展类（temporal_focus_expand、similarity_expand、relation_expand）以及处理类（llm_process，用于查询重写、证据过滤等）。所有技能共享同一套原语，因此结果可累积到统一经验结构中。

### 2.3 检索技能与路由器
- **检索技能**：κ = (cκ, ρκ)，其中 cκ 为技能描述与信息偏好，ρκ = (pκ,1, …, pκ,L) 为原语序列。技能按顺序执行原语，逐步更新证据状态，最终返回证据视图。技能以 Markdown 文件形式存储（如图 3 所示）。
- **技能路由器**：使用共享编码器 Enc(·)（实验中使用 Qwen3-Embedding-0.6B）编码查询和技能，通过可学习的评分函数 uθ(q, κ) 度量兼容性，并归一化为技能上的概率分布：

  Rθ(κ | q, K) = exp(uθ(q, κ)) / Σ_{κ'∈K} exp(uθ(q, κ'))

- **推理流程**：路由器选择最优技能 κ̂ = arg max Rθ(κ | q, K)，执行该技能得到证据状态，最后由 LLM 基于 (q, s_L) 生成答案 ŷ。

### 2.4 技能-路由器协同演化
- **双前沿机制**：
  - **能力前沿 Ct**：保留具有 oracle 侧价值的技能（即每查询可选最优技能时能达到的最佳效用），用于追踪已发现的检索能力上限。
  - **部署前沿 Bt**：面向路由器、经过验证可被路由器可靠选中的技能集，用于推理时的实际部署。
  - 二者分离使 ERSkill 能安全地探索新能力，同时保持部署稳定。
- **经验字典树（Experience Trie）**：将所有已探索的原语路径按前缀压缩存储，每个路径关联训练/验证回滚结果与前沿状态，用于检测重复候选、复用过往搜索经验。
- **技能候选生成**：通过编辑当前能力前沿的技能（增删/替换原语）生成新候选，并排除字典树中已记录的路径；由"分析器→设计器→生成器"三阶段智能体工作流实现。
- **能力前沿更新**：利用前沿重算算子 Φ(K; Q) 按效用排序，仅移除不会降低任何查询 oracle 得分的冗余技能，保证 oracle 覆盖率不下降。
- **路由器更新**：使用历史回滚实例窗口，以软标签交叉熵损失训练路由器（软目标由回滚得分经 softmax 得到）。
- **部署前沿更新**：仅在能力前沿变化时触发，根据路由增益 Δroute 与紧凑度容忍度 ξdrop 决定接受或拒绝候选部署前沿（γroute 为增益阈值）。
- **理论保证（命题 2.1）**：每一演化步均满足能力前沿与部署前沿在验证集上的 oracle 覆盖率非递减，证明了双前沿更新的 oracle 安全性。

## 6. 主要结论与发现

- **显著性能提升**：ERSkill 在三个基准上均取得最优整体表现，平均 F1 / BLEU-1 / L-J 得分较最强基线在 Qwen3-Next-80B-A3B-Instruct 上提升 31.3%、在 GPT-5.4-nano 上提升 28.1%。

- **跨数据集可迁移**：LoCoMo 上训练的技能与路由器可直接迁移至 LongMemEval 并保持最优，说明学到的检索技能捕获了可复用的检索行为。

## 7. 优点

- **新颖的研究视角**：首次将记忆检索本身作为可演化对象，打破"记忆内容自适应、检索行为固定"的不对称局面，开辟了检索侧演化的新方向。
- **设计优雅且工程完整**：技能抽象（原语组合）使检索行为可复用、可解释、可精炼；经验字典树避免了重复探索；双前沿机制在理论上（Proposition 2.1）保证了 oracle 覆盖率不降。
- **协同演化与稳定部署兼顾**："能力前沿"用于探索、"部署前沿"用于实践，通过路由增益门槛与紧凑度容忍度控制部署更新节奏，避免路由器未适应时的性能波动。
- **实验验证扎实**：涵盖多种骨干、多种数据集、多种基线、消融、迁移、稳定性、成本分析，并提供较高的成本-性能性价比证据。
- **可迁移性与泛化性良好**：训练出的检索技能表现出跨数据集的可复用性。

## 8. 不足与局限

- **训练期开销偏高**：技能演化依赖基于回滚的评估和 LLM-as-a-Judge 监督，即使推理端轻量，训练阶段成本仍较高（作者在 Limitations 中也承认）。
- **原语库固定**：固定的原语集合虽稳定了搜索空间、便于经验积累，但也从根本上限制了检索行为的表达边界；不支持在演化中发现新原语或新算子。
- **评估范围有限**：
  - 实验集中于长期记忆问答，未验证规划、工具使用、个性化交互、决策等更广泛的智能体任务；
  - 以 GPT-4o-mini 作为 judge 和 oracle 监督，可能存在评判偏差或对生成风格/长度的偏好风险；
  - 数据集中 LLM 生成的关系边（Cause/Reason 等）依赖提示词质量，噪声可能影响技能演化。
- **理论保证范围有限**：命题 2.1 只保证 oracle 覆盖率非递减，并不保证**路由准确率**或**端到端性能**的单调提升；文中案例也显示路由部署准确率可能暂时下降，只是后续能恢复。

- **迁移验证不足**：论文仅验证了 LoCoMo → LongMemEval 这一单向迁移路径，且迁移时未做任何额外训练；对于 LongMemEval → LoCoMo 的逆向迁移、跨骨干模型（如 Qwen 训练 → GPT 推理）的技能复用、以及跨任务类型（如从记忆问答迁移到规划、工具调用）的泛化性均未验证。因此，"学到的检索技能具有可复用性"这一结论目前仅在有限设置下成立，其适用范围仍有待更全面的实证检验。

## 9. 总体评价

ERSkill 的核心贡献在于开辟了"检索侧演化"这一新方向：不同于以往工作只让记忆内容或记忆构建策略自适应，它首次将**查询时的检索行为本身**作为可演化对象。通过技能抽象、路由学习与双前沿机制，该框架在保持部署稳定性的同时实现了检索策略的持续改进，并在多个长期记忆基准上取得了显著且可复现的提升。实验设计覆盖了多种骨干、基线与分析维度，证据链较为完整；训练与推理成本分析也说明其增益来源于针对性的证据构建而非单纯的内容堆砌。

当然，该工作仍是这一方向的"第一块基石"，尚存在训练开销偏高、原语表达边界固定、评估场景集中于记忆问答、理论保证局限于 oracle 覆盖率等不足。后续研究可在以下方向深入：突破固定原语库、实现原语或算子的自动发现；将技能演化推广到规划、决策、多智能体协作等更广泛的智能体任务；在理论上刻画端到端性能或路由准确率的收敛性；以及进一步压缩训练阶段的回滚与监督成本。总体而言，ERSkill 是一项问题意识敏锐、设计系统完整、实验扎实的工作，为智能体长期记忆的自适应访问提供了有价值的范式参考。
