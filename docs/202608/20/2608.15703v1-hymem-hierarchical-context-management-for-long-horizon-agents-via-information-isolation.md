## 摘要
大型语言模型（LLM）智能体在复杂的长期任务中往往表现不佳，因为其上下文会随时间推移变得越来越杂乱。随着交互的累积，详细的执行轨迹和中间输出占据主导地位，使模型难以保留和利用高层规划信息。现有方法大多通过对单一扁平上下文进行压缩或检索来解决此问题，这无法清晰区分不同类型的上下文信息，常导致推理能力下降。为应对这一挑战，我们提出HyMem，一种层级框架，明确将智能体的上下文划分为不同功能层。HyMem按功能组织上下文，将高层规划与执行及复杂分析分离。其隔离推理模块处理复杂子任务，而不会将中间推理轨迹添加到持久规划上下文中；其记忆管理模块通过结构化摘要保留跨上下文刷新的任务进展。这些组件减少了冗余上下文积累，保留了关键任务信息，并支持在有限上下文窗口内进行连贯的长期推理。在GAIA和Browsecomp-plus上的实验表明，使用DeepSeek-V4时，HyMem的平均Pass@1得分分别为66.7%和61.3%，比最强基线分别高出6.1和4.7个百分点。进一步分析表明，HyMem有效控制了推理上下文的增长，使模型能够在复杂长期任务中保持专注和准确性。

## Abstract
Large language model (LLM) agents often perform poorly on complex, long-horizon tasks because their context becomes increasingly cluttered over time. As interactions accumulate, detailed execution traces and intermediate outputs dominate the context, making it difficult for the model to retain and use high-level planning information. Most existing methods address this issue through compression or retrieval applied to a single, flat context, which does not clearly separate different types of context information and often leads to degraded reasoning. To address this challenge, we propose HyMem, a hierarchical framework that explicitly separates the agent's context into distinct functional layers. HyMem organizes context by function to separate high-level planning from execution and complex analysis. Its isolated reasoning module handles complex subtasks without adding intermediate reasoning traces to the persistent planning context, while its memory management module preserves task progress across context refreshes through structured summaries. These components reduce redundant context accumulation, retain task-critical information, and support coherent long-horizon reasoning within a limited context window. Experiments on GAIA and Browsecomp-plus show that, with DeepSeek-V4, HyMem achieves average Pass@1 scores of 66.7% and 61.3%, outperforming the strongest baseline by 6.1 and 4.7 percentage points, respectively. Further analysis indicates that HyMem effectively controls the growth of the reasoning context, allowing the model to maintain focus and accuracy across complex, long-horizon tasks.

### 一、核心问题与研究动机

- **问题的根源**：长时程（long-horizon）任务中，LLM智能体需要在宏观策略规划与微观工具操作之间无缝切换。然而，传统扁平化上下文架构（如ReAct）将高层规划信息与低层执行轨迹交错存储在单一序列中，随着交互累积，大量冗余的执行细节（工具输出、重试记录、格式噪音等）逐渐稀释稀疏但关键的规划信号。作者将这种现象形式化为**上下文稀释（context dilution）**：规划相关信息在总上下文中的密度随执行步数增加而持续下降（图1所示），导致智能体"迷失在细节中"。
- **现有方法的不足**：已有缓解手段（上下文压缩、外部记忆检索）大多作用于预先混合的扁平轨迹序列，无法从根本上区分规划信号与执行噪音。压缩易丢失关键推理链，检索难以保持时序逻辑、无法区分战略规划与离散执行步骤。这些策略只是处理上下文长度的"症状"，而非"信息类型混合"这一病根。
- **核心洞见**：有效的长时程上下文管理应从源头隔离不同类型的信息流，而不只是在事后进行压缩或检索。

### 二、方法论：HyMem框架

HyMem是一个**无需训练（training-free）的推理时（inference-time）控制框架**，其核心设计原则是**类型化上下文隔离（typed context isolation）**：规划、工具执行、隔离子任务推理、记忆整合分别维护在独立的上下文空间中，仅有受模式约束的消息允许跨越边界。

#### 1. 问题形式化

- 常规ReAct智能体维护扁平上下文： Ct = [P, q, (a1,o1), ..., (at,ot)]，其中混有规划相关信息 Zt 和执行级信息 Xt。
- 定义规划信息密度 ρt = |Zt| / |Ct|，随任务推进而降低，即"上下文稀释"。
- HyMem的目标是使规划器仅接收经过蒸馏的类型化返回消息，原始执行轨迹不进入规划上下文：I(C(p)t+1; Xt | Rt) ≈ 0。该目标通过接口设计而非可微优化来强制执行。

#### 2. 框架组成

- **Planner层（规划器）**：维护持久的决策上下文，包含系统提示、用户查询、三类结构化记忆（情节记忆Mepi、工作记忆Mwm、工具记忆Mtool）以及历史类型化返回。规划器只能发出四类动作：⟨TASK⟩（派发执行）、⟨ISO REASON⟩（派发隔离推理）、⟨FOLD⟩（触达记忆折叠）、⟨ANSWER⟩（返回答案）。
- **Executor层（执行器）**：接收工具使用指令后创建临时上下文，执行有界工具调用循环。原始观测经过**相关性条件蒸馏**（移除导航文本、重复段落、格式噪音等，保留命名实体、日期、数值、证据片段）后合成为结构化返回（含发现、证据、来源、状态、缺口），仅此返回被追加到规划器。执行器上下文随即销毁。
- **隔离推理模块（Isolated Reasoning）**：对于需要多跳分析、假设验证或冲突证据调和的子任务，创建独立的推理上下文（继承部分规划器状态和记忆），可调用执行器获取证据，但中间推理轨迹保持私密，仅返回结论、支持事实、来源、置信度、假设等结构化信息。
- **记忆管理模块（Memory Management）**：维护情节记忆、工作记忆、工具记忆三类可重写记忆，通过折叠操作（Fold）在触发条件满足时（如上下文利用率>99%、执行器调用≥5次、连续失败≥3次、规划轮次≥8次、工具调用≥10次）对所有记忆联合重写。采用**不对称记忆注入**：规划器接收全部三类记忆，隔离推理模块同样接收三类，而执行器仅接收工具记忆的精简摘要。

#### 3. 推理流程

- 规划器在每一步从其上下文中采样一个动作；执行器或隔离推理模块返回结构化结果后追加到规划器历史；折叠触发时重写记忆；最终由规划器输出答案。上下文的增长受限于类型化返回和重写后的记忆，而非原始工具轨迹或子任务推理的完整长度。

- Qwen3-32B与DeepSeek-V4两种骨干模型；所有框架的辅助LLM任务统一使用DeepSeek-V4保证一致性。

### 六、主要结论与发现

- **性能领先**：使用DeepSeek-V4时，HyMem在GAIA平均Pass@1达66.7%（超过ReAct 10.1个百分点、超过最强基线ReSum 6.1个百分点）；在Browsecomp-plus达61.3%（超过ReAct 4.7个百分点）。三级难度的GAIA均有提升，其中Level 3提升幅度最大。
- **难度分布**：Browsecomp-plus上，HyMem在简单题上略低于ReAct，但在中等和困难题上显著提升，尤其困难题Pass@1从14.0%升至30.0%——印证了"类型化隔离在需要持续规划与多步验证时最有效"的设计初衷。
- **消融验证**：移除隔离推理模块后，GAIA（Qwen3-32B）Pass@1下降18.6个百分点；移除记忆管理模块后，两个基准分别下降9.0和18.6个百分点。两个模块缺一不可。
- **上下文行为**：HyMem的总上下文虽继续增长（执行器与隔离推理的临时上下文），但持久规划器上下文增长缓慢，有效防止执行细节在任务过程中持续累积，使模型能维持对全局规范的推断能力。

### 七、方法亮点与优势

1. **问题视角新颖**：将"上下文稀释"正式化，从信息论角度刻画了规划信号被执行噪音淹没的机制，为长时程Agent研究提供了新视角。
2. **源头隔离而非事后补救**：相比压缩/检索方法，HyMem在信息进入决策上下文之前就限制其类型，从根本上阻止执行噪音的传播。
3. **模块化设计清晰**：规划、执行、隔离推理、记忆整理职责分明，信息边界由接口强制保证，无需额外训练，即插即用。
4. **结构化记忆体系完整**：情节/工作/工具三类记忆各司其职，分离了"已完成什么"、"当前要做什么"和"工具怎么用"三个层面的信息。
5. **资源效率有实证支撑**：通过token消耗和工具调用数对比表明，性能增益来自更优的信息分配而非更多资源消耗。
6. **报告了诚实局限**：明确指出方法对骨干模型指令遵循能力的依赖，以及跨骨干/基准的增益不均，显示了科学严谨性。

### 八、不足与局限

1. **实验规模受限**：Browsecomp-plus仅使用150题采样（虽然保证了难度均衡），GAIA仅使用文本子集，统计效力有限；对全量基准的表现未作验证。
2. **跨骨干鲁棒性不足**：在Qwen3-32B上，Browsecomp-plus任务中HyMem未超越ReAct基线，说明框架对弱骨干模型的收益并不稳定；消融实验在两个基准上使用不同骨干模型，削弱了消融结论的可比性。
3. **未报告算力细节**：缺少GPU型号、推理耗时等资源数据，难以评估框架在实际部署中的计算成本。
4. **辅助LLM依赖**：所有框架的辅助任务（摘要、记忆管理等）统一使用DeepSeek-V4，未分析辅助模型选择对整体性能的影响。
5. **额外控制开销**：HyMem引入隔离推理和记忆折叠等额外控制结构，虽然token消耗整体可比，但在简单任务上可能产生不必要的开销（简单题性能略低于ReAct也提示了这一点）。
6. **动态场景缺失**：实验局限于静态任务，未覆盖用户意图可能中途改变的多轮交互场景，论文在局限性中也承认了这一点。
7. **工程依赖**：方法的有效性高度依赖模型能否可靠遵循类型化控制指令并产出结构化返回，对模型能力有隐性门槛。
