## 摘要
基于大语言模型的智能体越来越依赖外部记忆来支持长期推理与交互。然而，主要瓶颈并非简单地存储过往经验，而是在相关信息分布于多次交互中时，恢复正确的证据集合。现有方法难以应对这一访问问题。全上下文方法需要噪声较大的长上下文搜索，扁平检索往往返回孤立且不完整的记录，而基于图的记忆系统构建成本高且会压缩丰富的事件上下文。我们提出RippleMem，一种长期记忆系统，用自适应联想回忆替代一次性检索。受线索依赖的情景回忆与联想补全启发，RippleMem将交互历史存储为富含线索的情景记忆单元，并以事件为中心组织成记忆图。给定查询时，它首先通过混合线索回忆相关记忆锚点，然后沿语义和结构关联从这些锚点扩展，以恢复缺失的支持性证据。这样，最初回忆的记忆不仅作为答案上下文，还作为补全回答所需证据的线索。在LoCoMo和LongMemEval-S上的实验表明，RippleMem在评估设置中取得了最佳整体性能，将LoCoMo上的LLM-as-a-Judge准确率提升了3.95%，在LongMemEval-S上提升了高达11.87%，同时将图构建成本降低了约30倍。

## Abstract
LLM-based agents increasingly rely on external memory to support long-horizon reasoning and interaction. However, the main bottleneck is not simply storing past experience, but recovering the right set of evidence when relevant information is distributed across many interactions. Existing approaches struggle with this access problem. Full-context methods require noisy long-context search, flat retrieval often returns isolated and incomplete records, and graph-based memory systems can be expensive to construct while compressing rich event context. We introduce RippleMem, a long-term memory system that replaces one-shot retrieval with adaptive associative recollection. Inspired by cue-dependent episodic retrieval and associative completion, RippleMem stores interaction history as cue-rich episodic memory units and organizes them in an event-centric memory graph. Given a query, it first recalls relevant memory anchors through hybrid cues, then expands from these anchors along semantic and structural associations to recover missing supporting evidence. In this way, initially recalled memories serve not only as answer context, but also as cues for completing the evidence needed to answer. Experiments on LoCoMo and LongMemEval-S show that RippleMem achieves the best overall performance across evaluated settings, improving LLM-as-a-Judge accuracy by 3.95% on LoCoMo and up to 11.87% on LongMemEval-S, while reducing graph construction cost by about 30x.

## 1. 论文的核心问题与整体含义（研究动机和背景）

长期记忆系统的核心瓶颈不在于"存储"，而在于"恢复"——当回答查询所需的证据分散在多次交互中时，如何组装出一套可回答的证据集合。具体存在三类失败模式：

- **全上下文方法**：需要噪声很大的长上下文搜索，模型易受"lost-in-the-middle"效应影响。
- **扁平检索（flat retrieval）**：通常停在最直接匹配的记录上，返回孤立、不完整的片段，遗漏关键支持证据。
- **图记忆系统**：无约束的图扩展可能遍历相关但不支持的记忆；且构建成本高昂，同时会压缩丰富的事件上下文。

论文核心观点：**长期记忆访问应当是"证据条件化"的，即已回忆的记忆应作为线索去恢复缺失的支持证据，而不是检索的终点**。

## 2. 方法论

### 2.1 核心思想

RippleMem受认知科学中**事件分割**（event segmentation）、**线索依赖的情景回忆**（cue-dependent episodic retrieval）和**联想补全**（pattern completion）等理论启发，将记忆访问建模为"自适应联想回忆"（adaptive associative recollection）。名称寓意类似涟漪从初始接触点扩散：从最初回忆的记忆锚点出发，沿局部关联扩展以恢复缺失证据。

### 2.2 系统架构（写-读设计）

**写阶段（Write Phase）**：

1. **Cue-Rich Episodic Memory Construction（富含线索的事件记忆构建）**
   - 将对话历史按重叠轮次窗口处理，由 schema 引导的 LLM 抽取 JSON 格式的记忆单元。
   - 每个记忆单元为 `mi = (ri, vi, Pi, Li, Ti)`：`ri` 为规范化事件重述，`vi` 为稠密向量，`Pi/Li/Ti` 分别为参与者、地点、时间线索。
   - 强制消解指代（如"she"→"Maya"）、锚定时间、拆分多事件窗口，无法确定时留空而非推断。

2. **Event-Centric Memory Graph（事件中心记忆图）**
   - 节点为记忆单元，边分为两类：
     - **语义关联**：`ssem(i,j) = cos(vi, vj)`，捕捉意义层面的接近度。
     - **结构关联**：基于参与者/地点的 Jaccard 重叠与时间间隔兼容度（重叠=1，否则指数衰减 `exp(-Δ/τ)`），加权聚合得到 `sstr(i,j)`。
   - **稀疏构建**：新记忆插入时，从语义近邻和线索索引获取有界候选池，按阈值和每节点度数上限（Ksem/Kstr=6）保留边。

**读阶段（Read Phase）**：

3. **Adaptive Associative Recollection（自适应联想回忆）**
   - **混合初始回忆**：`C0 = Csem ∪ Clex ∪ Ccue`，即语义搜索、词汇匹配、结构化线索匹配三种互补视图的联合。
   - **记忆锚点规划**：通过 schema 约束的回忆控制器 `Πrec` 决定是否继续、选择锚点 `Ar`、定义缺失支持目标 `gr`（目标重述+结构化线索）。
   - **锚点局部扩展**：从锚点沿语义/结构两类边在 `h` 跳邻域内收集候选，按与缺失目标的重合度打分，合并形成本轮支持集 `Sr`，更新证据状态 `C ← C ∪ Sr`。循环直到证据充分、无新支持或达到轮次预算 R=1。

4. **Evidence Assembly（证据组装）**
   - 按记忆 ID 去重合并，用确定性排序分数 `ρ(m) = λq·a(q,m) + λp·π(m) + λa·Ianc(m)` 排序，取 Top-K（K=30）作为最终证据上下文，交由 LLM 生成答案。

## 7. 优点

- **问题定义新颖**：明确将记忆访问重新定义为"证据恢复"而非"记录查找"问题，指出一次性查询匹配的固有缺陷。
- **理论指引明确**：认知科学中的事件分割、编码特异性、模式补全等理论为设计提供扎实的直觉基础，且作者明确声明是设计灵感而非机械建模。
- **写-读双阶段设计清晰**：线索丰富的事件记忆（写）与锚点局部扩展（读）形成闭环——已回忆记忆既作答案上下文又作恢复缺失证据的线索。
- **双通道关联机制灵活**：语义与结构（参与者/地点/时间）关联可分别遍历后合并，既捕捉概念相近的记忆，也捕捉共享情境线索但措辞不同的记忆。
- **稀疏图构建高效**：有界候选池+阈值+度数上限的设计使图稀疏且构建成本极低（约30倍降低），兼顾效果与效率。
- **实验严谨性高**：受控对比（RF-Mem 使用相同记忆单元和证据预算）、多基准验证、全面消融（组件消融+机制替换+对抗性问题）、分阶段效率分析、以及采用 GPT-4.1-mini 替代 LLM-EDGE 的成本效益验证。
- **对失败模式的分析深入**：附录 B.6 对无支持对抗性问题的分析表明系统在证据不足时能保守验证而非编造答案。

## 8. 不足与局限

- **场景覆盖单一**：仅评估文本型长期对话记忆基准，未覆盖多模态交互、具身智能体或工具使用环境，这些场景的记忆可能涉及视觉观察、动作和外部工具状态。
- **LLM 开销较高**：记忆抽取、查询分析、回忆规划均依赖 LLM 调用（每次查询平均 2,880.6 token 的规划开销），相比单次检索基线增加了延迟和成本；尽管可缓存/批处理缓解，端到端效率仍有优化空间。
- **时间线压力测试有限**：现有基准对持续增长的个人记忆（数年以上）、用户状态演化、记忆老化、隐私删除等场景缺乏充分测试。
- **消融中的细微矛盾**：去除结构线索后在某些类别（如开放域）出现 F1/BLEU-1 上升但判断准确率下降的情况，论文将其解释为"词汇重叠≠语义正确"，但这反映出不同指标间存在一定的不一致性。
- **阈值与权重为固定超参数**：语义边阈值0.85、结构边阈值0.60、证据排序权重等均在评估前固定，虽避免了调参偏差，但在不同应用场景可能需要重新配置，泛化性待验证。
- **无支持对抗性问题上表现略低于 RF-Mem**：Category-5 判断准确率 86.32% vs. RF-Mem 88.57%，虽然 RippleMem 在整体上更优，但这类"正确拒绝回答"的场景仍有改进空间。
