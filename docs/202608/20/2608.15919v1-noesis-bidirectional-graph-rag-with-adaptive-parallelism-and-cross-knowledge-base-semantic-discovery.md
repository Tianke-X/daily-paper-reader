## 摘要
基于知识图谱的检索增强生成（Graph-RAG）已成为将大型语言模型锚定到特定领域语料库的强大范式。然而，现有系统面临长期存在的局限：（1）静态分块会使长文档碎片化，丢失跨部分的语义连接；（2）摄取管道无法自适应扩展；（3）多领域部署要么需要会稀释检索精度的单体知识库，要么需要手动用户路由。我们提出Noesis，一种解耦的Graph-RAG架构，通过四种算法解决上述局限：（a）双向图遍历与图反馈上下文解析器，模拟带有记忆衰减的人类阅读；（b）借鉴TCP拥塞控制的AIMD并发控制器，实现23倍加速且零内存溢出事件；（c）Moesis，面向MoE模型的领域感知选择性量化，在12GB消费级GPU上实现6.3倍加速；（d）Mesh，具有运行时结构发现的跨知识库语义路由，使小型本地模型能够执行多跳跨域推理。在HotpotQA（1000个问题）上，Noesis取得59.5的EM / 74.7的F1，比GraphRAG高出+27.8 EM，同时使用35B本地模型而非GPT-4o进行图构建。在193页文档上的源文本验证确认，对于分块独立提取无法触及的长距离因果边，精度达到90%。

## Abstract
Retrieval-Augmented Generation over knowledge graphs (Graph-RAG) has emerged as a powerful paradigm for grounding large language models in domain-specific corpora. However, existing systems face persistent limitations: (1) static chunking fragments long documents, losing cross-section semantic connections; (2) ingestion pipelines do not scale adaptively; and (3) multi-domain deployments require either a monolithic knowledge base that dilutes retrieval precision or manual user routing. We present Noesis, a decoupled Graph-RAG architecture addressing these limitations through four algorithms: (a) Bidirectional Graph Traversal with a Graph-Feedback Context Resolver simulating human reading with degrading memory; (b) an AIMD Concurrency Controller adapted from TCP congestion control, achieving 23x speedup with zero OOM events; (c) Moesis, domain-aware selective quantization for MoE models achieving 6.3x speedup on 12 GB consumer GPUs; and (d) Mesh, cross-KB semantic routing with runtime structural discovery enabling small on-premises models to perform multi-hop cross-domain reasoning. On HotpotQA (1,000 questions), Noesis achieves 59.5 EM / 74.7 F1, surpassing GraphRAG by +27.8 EM while using a 35B on-premises model for graph construction rather than GPT-4o. Source text verification on a 193-page document confirms 90% precision on long-range causal edges inaccessible to chunk-independent extraction.

## 1. 核心问题与整体含义

Noesis 的提出源于现有 Graph-RAG 系统在生产部署中面临的三大瓶颈：

- **语义碎片化（Semantic Fragmentation）**：现有系统（如 Microsoft GraphRAG、LightRAG、LazyGraphRAG、HippoRAG）采用静态分块，各块独立处理，导致跨越块边界的概念被丢失或重复，图谱缺乏多跳遍历所需的密度。长文档中的跨章节因果联系（如第 1 章引入的概念与第 10 章的治疗结果之间的关联）无法被发现。
- **刚性并行度（Rigid Parallelism）**：现有摄取管道要么串行处理文档（据报道 GraphRAG 对中等语料索引用时数小时到数天），要么使用固定并行度导致在异构硬件上出现内存溢出（OOM）崩溃。缺乏运行时自适应并发控制和崩溃恢复机制。
- **跨域隔离（Cross-Domain Isolation）**：组织若维护多个专业知识库，要么合并为单体知识库（稀释检索精度并污染 LLM 上下文），要么要求用户手动选择目标库。现有 Graph-RAG 系统无法在查询时自动发现不同知识图谱之间的隐式结构连接。

论文的整体意义在于提出 Noesis——一个完全实现并验证的**解耦式分布式知识系统**，通过四种算法创新同时解决上述三个瓶颈，使**小型本地模型也能够高效地构建知识图谱并实现跨域多跳推理**，从而降低 Graph-RAG 的部署门槛。

## 2. 方法论：核心思想与关键技术细节

Noesis 的架构由五个独立组件组成，通过 REST API 和 Redis 消息队列通信：Cortex（LLM 推理引擎）、Neuron（知识图谱提取库）、Synapsis（编排层）、Retina（音视频摄取模块）、Mesh（跨 KB 语义路由器）。核心方法包含四种算法：

### 2.1 双向图遍历（Bidirectional Graph Traversal）
- **前向传播 + 图反馈上下文解析器**：文档按语义边界（标题、段落）切分为完整概念单元的切片后，逐片顺序处理。每片处理时从已提取节点中选择最相关的先前节点拼入上下文，模拟人类阅读中"记忆逐渐衰减"的过程。评分公式为：`score(n) = relevance(n) + recency(n)`，其中相关度通过 unigram+bigram 关键词重叠计算，近因项提供有界衰减加成。上下文预算随文档长度在最小/最大阈值之间线性扩展。
- **后向传播：基于度的重连**：前向完成后，识别早期低度节点，尝试将其与语义相关的后期节点重新连接，从而闭合前向无法看到的长距离依赖。仅当文档足够长、节点足够多时激活。

### 2.2 AIMD 自适应并行处理
- 借鉴 TCP 拥塞控制原理，将其适配到 RAG 管道编排场景：并发单位是文档而非数据包，状态通过 Redis 持久化以支持崩溃恢复。
- **算法规则**：初始保守并发值；连续成功数达到阈值后加性增（`C ← C+1`）；连续失败数达到阈值后乘性减（`C ← ⌊C/2⌋`）。
- **混合并行**：文档间并行（多文档同时处理），文档内顺序（切片必须顺序处理以维护图反馈上下文）——这个约束是双向遍历算法固有的，不能放松。

### 2.3 Moesis：领域感知选择性量化
- **三级流水线**：
  1. **自动领域剖析**：在 CPU 上对领域代表性文本进行推理，记录每层每个专家的激活频率，生成激活图。典型结果是约 5% 的专家为"热"专家。
  2. **选择性量化与 GPU 提升**：按激活集中度对每层分类——热层用 Q6_K（高位宽），冷层用 Q2_K（约 48% 体积削减）。量化后采用"只增不减"的 GPU 放置策略，消除重复 CPU↔GPU 传输。
  3. **运行时再适应**：领域变化时从原始全精度权重重新剖析和量化，防止累积精度损失。
- 量化评分函数：`score = sum(top_8_freq) × max(freq)`——激活集中、主专家频率高的层更重要，保留高精度。

### 2.4 Mesh：跨 KB 路由与语义发现
- **层次化指纹路由**：每个 KB 从图结构中导出语义指纹：`fp_KB = L2-norm(Σ wc·μc)`，其中 C 为 Leiden 社区集合，wc 为社区权重，μc 为社区节点的平均嵌入。使用余弦相似度进行多策略路由（指纹 → 社区重叠 → 标签匹配），再经 5 阶段融合（提取 → 置信度打分 → Jaccard 去重 → 重排序 → top-k 截断）。
- **运行时结构发现**：在初始检索后，通过块级语义发现（跨 KB 高相似块对）和节点级结构发现（1-hop 图扩展 + 嵌入相似度 + 度奖励），发现单独的 KB 索引中不存在的连接。
- **自然断点自适应阈值**：通过排序后的一阶差分（斜率）检测"膝点"，自适应确定每轮查询的相似度阈值，而非全局固定阈值。无清晰断点时回退到高百分位，并设有安全钳位防止阈值过低。

## 6. 主要结论与发现

1. **双向遍历显著提升图密度**：相比单遍基线，双向遍历产生的图密集得多（253 vs. 29 节点；257 vs. 36 边）；在 193 页文档上提取了 928 条文档内因果边，源文本验证精度达 90%。
2. **AIMD 控制有效**：13.4 MB 语料摄入 1 分 6 秒 vs. 25 分钟串行 = **23 倍加速**，所有配置零 OOM，且控制器状态在 worker 崩溃重启后仍持续可用（免预热恢复）。
3. **Moesis 使 MoE 模型在消费级 GPU 上可用**：12 GB 配置下提示处理 **6.3 倍加速**（22→139 t/s），生成 1.6 倍加速；6 GB 配置下原本直接 OOM，量化后稳定运行 160+ 分钟。
4. **Mesh 使小型模型具备跨域多跳推理能力**：2.3B 参数模型在无 Mesh 时无法连接跨域概念、输出含免责声明；有 Mesh 后能自主发现"身体接触→催产素→伴侣纽带"这类存在于任何单个文档之外的隐式结构连接，且零免责声明。
5. **架构贡献占主导**：消融显示，Noesis（图由 35B 模型构建）+ 2.3B 答案模型 ≈ BGE 稠密检索 + GPT-4o（约 100 倍大的模型），说明**检索架构贡献约 80% 的 QA 性能**，LLM 推理能力仅占约 20%。
6. **HotpotQA 表现**：EM 59.5 / F1 74.7，超 GraphRAG +27.8 EM；匹配预算（k=20）时 F1=76.12，与 HopRAG（76.06）持平，但图构建只用 35B 本地模型而非 GPT-4o。
