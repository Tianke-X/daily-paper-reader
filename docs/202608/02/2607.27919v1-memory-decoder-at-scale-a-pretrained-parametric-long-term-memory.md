## 摘要
仅解码器语言模型将长期记忆与推理纠缠在单一参数集中，使得独立扩展记忆容量变得困难。记忆解码器引入了一种参数化的长期记忆模块，但仅在相对较小的规模下进行了研究。在这项工作中，我们提出了大规模记忆解码器，将记忆模型扩展至69亿参数，并在3000亿词元上进行了预训练。在此数据规模下，索引与搜索的联合成本使得标准的Faiss流水线不可行。我们通过一种用于Faiss索引和检索的分布式流水线，以及kNN分布的稀疏、批量式加载，解决了这一瓶颈。在不同模型规模下，我们发现将更多参数分配给记忆，比单独扩展基础模型能带来更好的参数-性能权衡。在17个基准测试中，将69亿通用记忆与Pythia-410M配对，其平均得分从29.86提升至37.34，以少39%的总参数超越了Pythia-12B（37.24）。对于从6亿到140亿不等的Qwen3基础模型，17亿领域记忆在每一个规模上都将三个领域的平均得分提高了超过9分。总体而言，我们的结果表明，独立扩展预训练记忆为提升语言模型性能提供了一条更具参数效率的路径。

## Abstract
Decoder-only language models entangle long-term memory and reasoning in a single parameter set, making it difficult to scale memory capacity independently. Memory Decoder introduces a parametric long-term memory module but only studies it at a relatively small scale. In this work, we present Memory Decoder at Scale, scaling memory models up to 6.9B parameters and pretraining them on 300B tokens. At this data scale, the combined cost of indexing and search makes a standard Faiss pipeline infeasible. We address this bottleneck with a distributed pipeline for Faiss indexing and retrieval, together with sparse, batch-wise loading of kNN distributions. Across model scales, we find that allocating more parameters to memory yields a better parameter-performance tradeoff than scaling the base model alone. On 17 benchmarks, pairing a 6.9B general memory with Pythia-410M raises its average score from 29.86 to 37.34, surpassing Pythia-12B (37.24) with 39% fewer total parameters. For Qwen3 Base models ranging from 0.6B to 14B, 1.7B domain memories improve the average score across the three domains by more than 9 points at every scale. Overall, our results demonstrate that independently scaling pretrained memory offers a more parameter efficient path to improving language model performance.

## 1. 核心问题与研究动机

- **核心问题**：标准 decoder-only 语言模型将**长期记忆**与**推理能力**纠缠在同一个参数集中，导致无法独立扩展记忆容量。具体表现为：
  - 增加记忆规模必须同时增大整个模型参数，参数效率低。
  - 领域适配（如继续预训练或微调）需优化全部参数，训练成本高且有灾难性遗忘风险。
  - 缺少可插拔、可跨模型复用的独立记忆模块。
- **背景**：已有相关工作未充分解决这一纠缠问题：
  - **短期记忆**方向（如 Transformer-XL、StreamingLLM、InfLLM、LongRoPE）只关注输入上下文内的信息访问，未解决长期记忆与推理的参数纠缠。
  - **非参数长期记忆**方向（如 RAG、kNN-LM）依赖推理时的外部检索，带来存储与延迟开销。
  - Memory Decoder [Cao et al., 2026] 首次提出将 kNN 检索分布蒸馏到参数化记忆模块中，但仅在小规模（≤1B参数、百万级token语料）验证。
- **研究目标**：将 Memory Decoder 扩展到语言模型预训练规模（6.9B参数、300B tokens），研究记忆预训练是否能随模型和数据规模持续扩展，以及如何在基础模型与记忆之间最优分配参数预算。

## 2. 方法论：核心思想与关键技术

### 2.1 核心思想

- 训练一个**独立的参数化记忆模块** $M_\psi$，使其模仿非参数 kNN 检索器的输出分布，从而把"外部检索信号"蒸馏进网络权重中。
- 推理时，冻结的基础模型 $M_\theta$ 与记忆模块 $M_\psi$ **并行处理同一上下文**，将两者的下一 token 分布做线性插值作为最终预测。
- 记忆模块可**独立预训练、独立扩展、推理时可热插拔**，基础模型完全冻结。

### 2.2 训练目标（核心公式）

记忆模块的损失函数：

$$\mathcal{L}_{\text{mem}} = \beta \, D_{\text{KL}}\left(p_{\text{ret}}(\cdot|c_t) \,\|\, p_\psi(\cdot|c_t)\right) + (1-\beta)\left[-\log p_\psi(x_t|c_t)\right]$$

- 第一项：KL 散度，使记忆分布 $p_\psi$ 模仿 kNN 检索分布 $p_{\text{ret}}$（提供比单一 gold token 更丰富的监督信号）。
- 第二项：标准语言建模损失，防止记忆偏离语料分布。
- $\beta$ 控制检索监督的贡献权重。

### 2.3 推理时插值（核心公式）

$$p_{\text{final}}(y|c_t) = (1-\alpha)\, p_\theta(y|c_t) + \alpha\, p_\psi(y|c_t)$$

- $\alpha \in [0,1]$ 为插值系数，在验证集上调节后固定。

### 2.4 大规模 kNN 分布构建（分布式 Faiss 流水线）

在 207B tokens 规模下，直接构建 kNN 分布面临二次方级别的索引与搜索瓶颈，标准 Faiss 流水线不可行。论文提出了三步解决方案：

1. **嵌入压缩（Embedding Compression）**：训练 OPQ256 变换，将 4096 维的隐藏状态压缩为 256 维搜索向量，降低存储和距离计算成本。
2. **索引分片（Index Sharding）**：使用 HNSW 作为量化器学习 IVF 划分，每个分片存储连续质心范围的 IndexIVFPQ 子索引，支持独立 GPU 搜索。
3. **大规模并行检索（Parallel Retrieval）**：HNSW 将查询路由到对应分片队列，各 GPU 并行执行局部 IVFPQ 搜索，writer 进程合并候选并输出 top-K 稀疏分布。

### 2.5 稀疏存储与分布式加载

- **稀疏 kNN 分布存储**：$p_{\text{ret}}$ 的支撑集不超过 $K$ 个 token，存储量从 $O(N|\mathcal{V}|)$ 降至 $O(N+M)$（$N$ 为分布行数，$M$ 为保留的 token-概率对）。在 Pile 上每行平均保留 64.95 个 token-概率对，相对稠密存储约节省 250 倍空间。
- **分布式流式加载**：预处理时为每个 packed 样本附加对齐的分布行范围，训练时基于偏移量直接读取所需分片，保证 shuffle 后 token 与检索监督对应关系不丢失。

### 2.6 领域记忆预训练

- 对每个领域语料（生物、法律、金融），先对数据构建器模型（Qwen3-4B）做继续预训练，再构建 kNN 分布用于监督独立的领域记忆模块。

- **数据构建成本**：在 207B tokens 上构建 kNN 分布需一次离线索引与检索，且使用 4096 维 Pythia-6.9B 隐藏状态，产生了大量预处理开销（论文在 Limitation 中明确承认）。

## 5. 实验数量与充分性

### 5.1 实验规模概览

| 实验类别 | 数量与内容 |
|---|---|
| 通用记忆主实验 | 3 个骨架（1.4B/2.8B/6.9B）× 17 个基准，共 51 个 task-scale 组合 |
| 跨骨架迁移 | 18 种 Base+Memory 配置（410M~6.9B × 记忆 1.4B~6.9B）|
| 领域记忆 | 5 个 Qwen3 骨架 × 3 个领域（15 个评估），+ 3 个基线 |
| 跨词表迁移 | 2 个 OLMo 骨架 × 3 个领域，3 个基线 |
| 记忆大小消融 | 通用（3 大小）、领域（0.6B vs 1.7B） |
| 训练预算消融 | 1.5 vs 5 epochs（通用）、20% vs 100%（领域） |
| 训练目标消融 | 记忆 vs 同规模 CPT 模块 |
| 少样本鲁棒性 | 0-shot / 3-shot / 5-shot |
| 检索监督保真度 | 1024 个样本，4 种指标 |
| 可提取记忆评估 | 2 种探针，各 1024 个训练样本 |
| 插值系数敏感性 | 21 个系数 × 6 个任务 × 3 个规模 |

### 5.2 充分性与客观性评价

- **优势**：
  - 实验覆盖范围广，从 410M 到 14B 的多系列骨架、多领域、多基准，结论具有较强泛化性。
  - 对比设计相对公平：CPT 和 LoRA 在训练数据、FLOPs、参数量上与记忆模块对齐；attached module 控制实验排除了插值接口本身的贡献。
  - 消融实验系统性强：记忆大小、训练预算、目标函数、少样本、插值系数均有覆盖。
  - 附带可提取记忆评估，探讨了记忆化的安全性维度，角度新颖。
- **需要注意的偏差风险**：
  - 通用记忆实验只使用 Pythia 骨架；领域记忆实验只使用 Qwen3 骨架，跨家族验证仅限 2 个 OLMo 模型，外部效度有限。
  - 插值系数 $\alpha$ 在验证集上调优后用于测试，但不同任务/规模系数差异很大（0.0~1.0），部分任务（如 LogiQA 2.8B 中 $\alpha=0$）实际未使用记忆，表明收益存在任务选择性。
  - GPQA-main 仅报告 10 个随机种子的平均值；In-context learning 对比中部分任务（如 TruthfulQA、HaluEval、GPQA-main）被排除在少样本平均之外，选择标准未完全透明。
  - 部分基准的最强提升集中在少数任务（如 TriviaQA 提升巨大），"47/51 组合提升"这一统计虽强，但幅度差异较大。

## 6. 主要结论与发现

1. **记忆扩展比骨干扩展更参数高效**：Pythia-410M + Mem-6.9B 在 17 个基准上达到 37.34，超过 Pythia-12B（37.24），总参数少 39%。在相同总参数量下，Base+Memory 配置优于单独扩展骨干。
2. **通用记忆在各规模均一致有效**：1.4B/2.8B/6.9B 骨架附加等规模记忆后，AVG 分别提升 +1.60/+1.60/+1.49 分；51 个任务-规模组合中 47 个提升、1 个持平。
3. **跨骨架迁移有效**：预训练记忆可服务不同规模的基础模型，无需重新训练；小骨架配大记忆的收益最大。
4. **领域记忆普适性强**：1.7B 领域记忆在 Qwen3 0.6B~14B 所有规模上提升平均分超过 9 分；三个领域全部 15 个评估均提升。
5. **跨词表迁移可行**：仅用 20% 训练预算，Qwen3 领域记忆迁移到 OLMo 词表后，OLMo-2-7B 提升 4.26 分，OLMo-3-7B 提升 7.77 分。
6. **记忆收益主要来自训练目标而非接口**：对比同规模 CPT 模块，记忆在 BioInst 上高 8.71~10.21 分，在 LawBench 上高 1.68~3.93 分。
7. **记忆训练提升内容可提取性**：记忆模型比 CPT 模型更容易从部分上下文恢复训练数据（EM@8,16 从 42.4%→49.7%；领域锚点补全从 22.6%→56.5%）。
8. **记忆忠实于检索监督**：top token 匹配率 86.62%，Pearson $r = 0.917$，表明记忆学习到了检索分布的完整结构（含概率分配）而非仅模式。

## 7. 方法优点

- **架构创新**：将长期记忆与推理解耦为独立参数模块，支持记忆的热插拔与跨模型复用，从根本上改变"记忆必须随骨干扩展"的范式。
- **工程贡献突出**：分布式 Faiss 流水线 + 稀疏存储 + 流式加载，解决了 207B 规模下 kNN 分布构建的实际工程瓶颈；稀疏存储 250 倍压缩比极具实用价值。
- **实验严谨性**：控制变量设计严谨（训练数据、FLOPs、容量、接口对齐），使"记忆目标有效"的结论具有较强因果说服力。"Attached module control"实验明确区分了记忆训练目标与插值接口的贡献。
- **案例分析有说服力**：HotpotQA 上下文的词级记忆贡献可视化直观展示了记忆模型对实体/属性的强化。可提取记忆评估从一个新颖角度揭示了记忆机制的特性差异。
- **通用性与可扩展性**：记忆收益在不同骨架家族（Pythia、Qwen3、OLMo）、不同规模（0.6B~14B）、不同领域（生物、法律、金融）上一致出现，结论稳定性好。

## 8. 不足与局限

- **预训练阶段离线成本高**：虽然推理时无需检索，但构建 kNN 目标分布仍需要大规模索引与检索，是额外的离线预处理负担（论文在 Limitation 中承认）。这一成本随语料规模增长而增加，论文未报告完整的构建时间/成本分析。
- **跨领域泛化偏差**：领域记忆在生物和法律任务上提升显著，但在金融（FinEval）上部分配置提升较小（3.04 分）。知识密集任务收益不均衡，记忆的领域适配性不统一。
- **推理延迟问题**：基础模型与记忆需并行处理同一上下文，总计算量相当于两个模型合并，尽管可并行化，但对单个设备部署仍不友好。
- **固定插值系数 $\alpha$**：当前使用全局或任务级固定系数，无法根据输入动态调整记忆贡献；最优 $\alpha$ 随任务和规模变化很大，实际部署需要额外调参。
- **实验范围局限**：
  - 通用记忆仅基于 Pythia 骨架，未在更多现代模型（如 Qwen3、Llama）上验证通用记忆。
  - 跨词表迁移实验仅用 20% 预算，未探索全预算下是否还有更大收益空间。
  - 对 TruthfulQA/HaluEval 的"幻觉鲁棒性"收益并不一致（部分配置低于基线），记忆对幻觉的影响是非单调的，需更深入分析。
- **记忆可提取性上升的安全风险**：记忆模型比 CPT 更容易从部分上下文恢复训练数据（EM@8,16 提升到 49.7%，领域锚点补全 56.5%），这既证明了记忆模块更强的编码能力，也暗示了**潜在的数据泄露/隐私风险**。论文未评估提取内容的质量边界或提出缓解措施。
- **性能提升的实际来源尚不明确**：记忆模块的性能增益本质上来源于 kNN 检索器对训练数据中"相似上下文"的显式利用，这种外部知识被蒸馏进参数中。但其在开放式生成中是否会固化为错误知识（来自 kNN 检索中的噪声邻居）仍需进一步评估。
- **训练时长和能耗未报告**：论文未给出总 GPU 小时数或训练墙钟时间，影响资源可复现性评估。
