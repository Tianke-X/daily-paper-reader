## 摘要
大型语言模型（LLMs）已成为自动化进化优化的强大工具，但现有方法在模式复用、错误感知精炼以及跨不同任务的检索鲁棒性方面仍然受限。为解决这些局限性，我们提出了OptGraph，这是首个引入图检索增强生成（GraphRAG）的优化智能体工作流。具体而言，OptGraph首先将可复用的经验构建为类型化图，捕捉建模模式、问题形式化、实现细节和错误修正之间的关系。在推理阶段，OptGraph利用图邻域信息丰富检索到的知识，提供结构化上下文以改善建模、验证和迭代精炼。此外，OptGraph支持自适应知识更新，能够在无需调整LLM参数的情况下，将执行轨迹和验证反馈提炼为可复用的图知识。在基准数据集上的大量实验表明，我们提出的OptGraph的平均精确准确率比最先进的基于提示的自动化优化框架高出8.9%。我们的代码已在https://github.com/xianchaoxiu/OptGraph上公开。

## Abstract
Large language models (LLMs) have emerged as a powerful tool for automated evolutionary optimization, but existing methods remain limited in pattern reuse, error-aware refinement, and retrieval robustness across diverse tasks. To address these limitations, we propose OptGraph, the first optimization agentic workflow that introduces graph retrieval-augmented generation (GraphRAG). Specifically, OptGraph first constructs reusable experience as a typed graph, capturing the relationships among modeling patterns, problem formalization, implementation details, and error corrections. In the inference stage, OptGraph leverages graph neighborhood information to enrich retrieved knowledge, providing structured context to improve modeling, verification, and iterative refinement. Moreover, OptGraph supports adaptive knowledge updates, enabling the distillation of execution traces and verification feedback into reusable graph knowledge without ndertaking LLM parameter tuning. Extensive experiments on benchmark datasets show that our proposed OptGraph achieves an average exact accuracy 8.9% higher than the state-of-the-art prompt-based automated optimization frameworks. Our code has been made available at https://github.com/xianchaoxiu/OptGraph.

## 1. 核心问题与整体含义（研究动机和背景）

- **背景**：优化问题在交通、金融、制造等领域至关重要，但实际瓶颈往往不在于求解模型，而在于**建模**——从业者需要把模糊的自然语言描述转化为决策变量、目标函数和约束，再编写成可执行的求解器代码（如 Gurobi、CPLEX）。这一过程高度依赖运筹学专业知识，耗时且难以普及。
- **现有进展**：基于 Transformer 的大型语言模型（LLM）在数学推理、程序合成和算法设计上展现出潜力，推动了 LLM 驱动的自动化优化。现有方法分为两类：
  - **学习型**（如 ORLM、OptMATH、LLMOPT、OR-R1）：使用优化数据微调或强化学习。
  - **提示型**（如 Chain-of-Experts、OptiMUS、OptiTree、Lean-LLM-OPT）：围绕预训练 LLM 构造推理、检索、智能体协作等工作流。
- **三个关键缺陷**（论文通过数据分析揭示）：
  1. **模式复用不足**：优化数据集包含异构但可复用的建模模式（如目标相关、比例、差分、分配、调度、专门 OR 结构），现有方法把知识作为孤立例子或静态模板，未按问题类型组织。
  2. **错误感知不足**：LLM 失败不仅包含代码错误，还有反复出现的公式化错误（目标错误、约束缺失、逻辑错误、边界错误、数据解释错误），需要结合错误知识的迭代修复机制。
  3. **检索鲁棒性差**：朴素 RAG（如 OptiMUS 中的检索增强）可能因文本相似性与建模逻辑不匹配而**降低**性能，检索必须保留结构化关系。
- **核心问题**：能否用**图检索增强生成（GraphRAG）** 将问题模式、公式、代码、典型错误和修复提示组织成结构化图，从而提升自动化优化的准确性、鲁棒性和经验复用能力？

## 2. 方法论：核心思想与关键技术细节

OptGraph 被作者称为**首个引入 GraphRAG 的优化智能体工作流**，包含四个主要步骤（整体流程见论文 Fig. 2）。

### 2.1 核心思想
- 将可复用的优化知识封装为**有向异构图**，节点类型包括：`Problem Type`（问题类型）、`Variant`（变体）、`Description`（描述）、`Math Model`（数学模型）、`Code Snippet`（代码片段）、`Typical Error`（典型错误）、`Fix Hint`（修复提示）。
- 推理时，检索**图邻域信息**而非孤立文本片段，为建模、校验和修复提供结构化上下文。
- 通过执行轨迹和验证反馈**自适应更新图**，实现无需 LLM 参数微调的知识积累。

### 2.2 技术细节

- **图构建（Step 1）**：
  - 数据来源：优化基准、求解器轨迹、人类专家经验、领域文献。
  - 知识提取：错误挖掘、结构解析、模板抽取、模式蒸馏。
  - 图定义：$G=(V,E,\tau,\rho)$，节点类型见式 (2)。
  - 初始图包含 15 个种子模式，更新后可扩展到 48 个。

- **知识建模（Step 2）**：
  - 对问题 $P$，计算与变体节点的相关性 $S(P,v)$；
  - 选出 top-$k$ 变体节点 $R_k(P)$；
  - 扩展邻域得到检索上下文 $K(P) = \bigcup_{v\in R_k(P)}(\{v\}\cup \mathcal{N}(v))$；
  - 问题识别智能体确定问题类型与变体；
  - 建模智能体 $A_{model}$ 生成数学公式 $\hat{M} = A_{model}(P, K(P))$；
  - 代码合成智能体 $A_{code}$ 生成可执行代码 $\hat{C} = A_{code}(P, \hat{M}, K(P))$。

- **验证机制（Step 3）**：
  - 执行代码 $(o,\hat{y},s)=\text{Exec}(\hat{C})$，其中 $o$ 输出、$\hat{y}$ 数值答案、$s$ 执行状态；
  - 三方面一致性检查：**目标验证**（目标函数与问题意图一致）、**约束验证**（约束覆盖所需条件）、**程序验证**（程序可执行、答案可解析）；
  - 验证结果 $z=V(P,\hat{M},\hat{C},o,\hat{y},s)\in\{0,1\}$；
  - 若失败，检索 `Typical Error` 和 `Fix Hint` 节点，由修复智能体迭代更新公式与代码（公式 11），最多 3 轮；
  - 记录完整执行轨迹 $\xi=\{(η^{(t)}, z^{(t)}, f^{(t)})\}$。

- **图更新（Step 4）**：
  - 分析执行轨迹，提取候选图更新 $\Delta G_q = U(\xi_q)$；
  - 将候选节点/边合并或插入到当前图：$G^{(q)} = G^{(q-1)} \oplus \Delta G_q$；
  - 新知识被保留，供后续任务复用，无需修改 LLM 参数。

## 6. 主要结论与发现

- **OptGraph 在全部 6 个数据集上均取得最佳精确准确率和 5% 容忍准确率**，平均精确准确率 75.4%（第二好 66.5%，提高 8.9%），平均 5% 容忍准确率 83.2%。
- 在复杂数据集上优势更明显：如 OptMATH 上精确准确率比第二名高 13.9 个百分点，5% 容忍准确率高 15.6 个百分点；IndustryOR 和 MAMO-C 上也显著领先。
- 独立 LLM 基线（GPT-5.1 等）平均性能明显低于 Agent 与图引导方法，说明**仅靠通用 LLM 不足以完成稳定优化建模**。
- 消融表明：**GraphRAG 和验证机制缺一不可**，同时移除时在 MAMO-C、OptMATH 上性能下降超过 20%。
- 朴素 RAG 在所有三个测试数据集上**损害**原框架性能（如 IndustryOR 从 52.0% 降到 50.0%），而 GraphRAG 则大幅提升，说明**结构化关系检索对优化建模至关重要**。
- 验证轮次以 3 轮为最佳，继续增加会导致过修正。
- GraphRAG 可作为**即插即用模块**，一致提升其他框架（CoE, OptiMUS, Lean-LLM-OPT）的准确率。
