## 摘要
Transformer的深度并非均匀使用：较低层和中间层构建语义表示，而较高层则逐渐将它们特化用于预测。我们将这种分工转化为CoMem（理解记忆），它仅通过中间层写入每个上下文块，检索固定数量的缓存残差状态，并在结果包上重新计算查询条件化的高层。在固定的检索预算下，模型侧的读取计算和内存与存储的上下文长度无关。我们在统一的免聊天模板协议下评估了继续训练的Qwen3-8B基础语言模型。主干网络被冻结；旗舰版本仅在纯PG19上训练秩为32的自蒸馏LoRA，我们另外报告一个免适配器分支。CoMem在RULER上达到97.05，在LoCoMo上达到38.27，而全上下文KV-Direct为34.59；对话记忆优势在对话簇重采样和独立评判下依然存在。在其他长上下文和长文档任务上的结果既展示了受限检索的益处，也暴露了其窗口内压缩代价。受控深度扫描表明，更深的缓存降低了每次查询的重计算，但引入了保真度损失，而自蒸馏能大幅修复这一损失。在NVIDIA H20上以128k进行的独立免适配器效率对照中，CoMem使用18.26 GB而非89.36 GB，并实现了7.83倍的前缀填充加速。这些结果表明，长上下文记忆可以沿层轴组织，而不仅仅是沿词元轴。

## Abstract
Transformer depth is not used uniformly: lower and middle layers build semantic representations, while upper layers increasingly specialize them for prediction. We turn this division of labor into CoMem (Comprehension Memory), which writes each context chunk only through an intermediate layer, retrieves a fixed number of cached residual states, and recomputes the query-conditioned upper layers over the resulting pack. For a fixed retrieval budget, model-side read compute and memory are independent of stored-context length. We evaluate a continued-trained Qwen3-8B base LM under a unified chat-template-free protocol. The backbone is frozen; the flagship trains only a rank-32 self-distillation LoRA on plain PG19, and we report an adapter-free arm separately. CoMem reaches 97.05 on RULER and 38.27 on LoCoMo versus 34.59 for full-context KV-Direct; the dialogue-memory advantage survives conversation-cluster resampling and an independent judge. Results on additional long-context and long-document tasks expose both the benefits of bounded retrieval and its in-window compression tax. Controlled depth sweeps show that deeper caching lowers per-query recomputation but incurs a fidelity loss that self-distillation substantially repairs. In a separate adapter-free efficiency control on an NVIDIA H20 at 128k, CoMem uses 18.26 GB rather than 89.36 GB and achieves a 7.83x prefill speedup. These results show that long-context memory can be organized along the layer axis, not only the token axis.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：Transformer 的深度并非均匀使用——低层和中层已经构建出语义可访问的表示，而高层逐渐将表示特化为当前查询的预测。现有长上下文方法多沿**词元轴（token axis）**组织记忆（如 KV 缓存压缩、检索式文本召回），忽略了深度这一可能的组织维度，导致模型侧读算和内存随上下文长度增长。
- **核心问题**：能否将长上下文记忆组织在**层轴（layer axis）**上，使模型侧在线读取的计算与存储开销不再随已存储上下文长度增长？
- **核心含义**：通过“浅写入 + 深度分割 + 有界检索 + 高层重算”，可以在不扩展原生位置窗口、不依赖全上下文 KV 的情况下实现超出原生窗口的可用记忆；同时揭示深度分割存在“查询条件化读取损失”，可通过轻量自蒸馏修复。

## 2. 方法论

### 2.1 核心洞察

- 语义内容在低/中层（约 0.45 L）即可访问，而零样本“可读深度”随模型规模增大而加深；上层状态更多受查询条件化影响，因此缓存的状态不应作为最终表示直接使用。
- 长距离瓶颈主要在于**选择（selection）而非保真度（fidelity）**：在有 oracle 选择器时，RULER 针检索可达 100%；低层缓存本身并不构成主要障碍。

### 2.2 算法流程（CoMem，算法 1）

- **Write（写入）**：将文档切分为不重叠的 512-token 块，每块从位置 0 重新开始 RoPE，仅通过层 [0:j] 前向传播，缓存每个 token 的残差状态 hj（j = 12，共 36 层），存于外部存储，以块文本为键。
- **Select（检索）**：使用迭代 BM25（top-12、跳数 4、自动 3 轮前沿扩展、去重）从外部索引中选取有界数量的相关块。
- **Read（读取）**：将 [BOS；选中的 hj；query 的 hj] 按文档顺序打包，使用全新连续 RoPE，重算层 [j:L]（约 6.5k token），执行完整因果跨块注意力，输出 next-token logits。
- **存储效率**：每 token 缓存为 1 个 bf16 残差向量（8 KB），对比完整 bf16 KV 的 144 KB，比率 d / (2L·dkv) = 1/18（Qwen3-8B：d=4096，L=36，nq=32，nkv=8）。
- **自蒸馏**：冻结主干，在层 12–35 上训练 rank-32 LoRA（α=64、无 dropout、层 12–35 的所有注意力和 MLP 投影），目标为双向 KL（0.6·KL(p‖q) + 0.4·KL(q‖p)），教师为 j=0 的冻结模型，取教师 top-64 logit 支持集，无附加交叉熵项；数据仅为 PG-19 训练集的 2048-token 窗口，无任何长上下文合成数据、检索或任务监督。

## 6. 主要结论与发现

- **深度可作为可测量的复用轴**：语义内容深度约为 0.45×L 且跨规模近乎不变；零样本可读深度随规模加深，二者之间的差距定义了适配修复空间（小模型空间大，32B 时消失）。
- **CoMem 实现有界读取**：top-12 BM25 检索 + 层 12 缓存 + 上层重算，使模型侧在线读取约 6.5k token，与存储上下文长度无关；写入为线性、可复用。
- **核心基准结果**：CoMem + LoRA 在 RULER 达 97.05、LongEval 69.0、LoCoMo Judge 38.27（优于 KV-Direct 34.59，配对 95% 引导 CI [2.34, 7.27]，对话簇 bootstrap 正值，DeepSeek-V3 审计保持顺序）；LongBench macro F1 与 KV-Direct 基本持平（12.15 vs 12.17）；BABILong qa5 领先（68.7）。
- **效率**：H20 上 128k 时显存由 89.36 GB 降至 18.26 GB，prefill 加速 7.83×；编码解码阶段不重跑整包，保持在密集模式 11% 以内，128k 时 1.07× 更快。
- **消融结论**：更深的缓存降低查询时开销但损害冻结读保真度；自蒸馏在相同 j=12 下恢复 LoCoMo 13.75 分；跨块注意力对多事实消歧至关重要；检索宽度并非越大越好（约 17k 扩展在 16k 后劣于约 6.5k 聚焦配置）。

## 7. 优点

- **动机清晰且有实证支撑**：用探针、因果截断、深度扫描三类证据支撑“深度分工”假设，而非先验架构设计。
- **方法简洁、正交**：CoMem 不修改主干、不训练记忆池、无检索监督，仅用一个轻量 LoRA 修复界面，与现有 token 轴压缩/检索方法正交。
- **存储效率显著**：每 token 缓存 1/18 于完整 bf16 KV，可复用写入，适合多查询场景。
- **实验控制较严谨**：统一免聊天模板协议、固定全局检索配置、受控固定包深度扫描、同包消融；LoCoMo 的不确定性分析覆盖了对话级依赖。
- **可迁移性验证**：跨模型规模（0.6B–32B）、稀疏 MoE（30B-A3B、Hy3 80 层）、检索无关 HCache 路径均可移植。

## 8. 不足与局限

- **窗口内压缩税**：BABILong qa1/qa2 明显弱于全上下文 KV-Direct，说明有界读取并不统一优于全上下文；必须承认全上下文在窗口内仍是强力参考。
- **位置范围未扩展**：Qwen3-8B 未使用 YaRN，>40,960 的结果只是无扩展压力参考，不能宣称对 YaRN 扩展全上下文模型有优势。
- **检索限制**：仅 BM25 词法检索，未覆盖语义/稠密检索，相关段落与查询表面形式差异大时可能失效；多跳自然工作负载的检索延迟未测量。
