## 摘要
长视界LLM代理会累积推理轨迹、动作和工具观测结果，这些内容最终可能超出模型的固定上下文窗口。现有的压缩方法通过丢弃、总结或检索早期信息来解决这一限制，但它们可能删除任务关键细节或无法可靠地恢复这些信息。我们提出了ARC（可寻址召回压缩），一种将存档存储与主动上下文呈现分离的上下文管理框架。ARC将工具观测结果存储在只追加、ID可寻址的日志中，并在需要压缩时用紧凑的引用替换较旧的观测结果。代理随后可以使用这些标识符请求存储的内容，而无需重新执行相应的工具或仅依赖基于相似性的检索。我们使用具有16k上下文窗口的Qwen3-8B和具有32k上下文窗口的Qwen3-32B评估了ARC。在Needle-in-a-Haystack评估中，ARC的平均精确答案准确率达到99.40%，而我们的评估中最佳基线的准确率为88.12%。在我们的硬件成本模型下，ARC还减少了估计的服务时间和HBM流量。在LongBench-v2 Hard子集上，ARC的平均准确率为29.97%，而最佳基线为28.25%。这些结果表明，相对于评估的上下文管理基线，在测试设置下，基于地址的显式召回可以提高信息保留和服务效率。

## Abstract
Long-horizon LLM agents accumulate reasoning traces, actions, and tool observations that can eventually exceed a model's fixed context window. Existing compaction methods address this limitation by discarding, summarizing, or retrieving earlier information, but they may remove task-critical details or fail to recover them reliably. We propose ARC (Addressable Recall Compaction), a context-management framework that separates archival storage from active-context presentation. ARC stores tool observations in an append-only, ID-addressable log and replaces older observations with compact citations when compaction is required. The agent can subsequently use these identifiers to request stored content without re-executing the corresponding tools or depending solely on similarity-based retrieval. We evaluate ARC using Qwen3-8B with a 16k context window and Qwen3-32B with a 32k context window. On the Needle-in-a-Haystack evaluation, ARC achieves an average exact-answer accuracy of 99.40%, compared with 88.12% for the best-performing baseline in our evaluation. ARC also reduces estimated serving time and HBM traffic under our hardware-cost model. On the LongBench-v2 Hard subset, ARC obtains an average accuracy of 29.97%, compared with 28.25% for the best-performing baseline. These results indicate that explicit, address-based recall can improve information retention and serving efficiency relative to the evaluated context-management baselines under the tested settings.

## 一、论文的核心问题与整体含义（研究动机与背景）

长视界（long-horizon）LLM代理在持续运行中会不断累积推理轨迹、动作历史和工具观测结果。由于当代自回归语言模型在每次调用之间本质上是无状态的，代理必须将整个轨迹作为"工作记忆"重新发送给模型。这一机制带来了一个硬性瓶颈：**上下文窗口限制（context-window limit）**。一旦累计轨迹超过模型的上下文上限，下一次模型调用就会直接失败，代理陷入瘫痪。对于长时规划、复杂软件工程、开放网络浏览等任务，上下文溢出并非罕见边界情况，而是必然发生的事件。

- 现有压缩/压缩方法主要分为四类：朴素截断（Naive Truncation）、分层摘要（Hierarchical Summarization）、状态折叠（State Folding）、检索增强生成（RAG）记忆。
- 这四类方法本质上**都是有损（lossy）**的：信息被剪除、改写或向量化后，精确恢复不再有保证。若被丢弃的内容包含任务关键信息（如变量名、错误字符串、用户约束），代理必须付出高昂代价重新推导或产生幻觉，误差会在长轨迹中不断积累放大。
- 核心研究问题：**能否在保持活动提示（active prompt）长度受限的前提下，让轨迹压缩做到严格无损（lossless）？**

## 二、论文提出的方法论

### 核心思想

ARC（**A**ddressable **R**ecall **C**ompaction，可寻址召回压缩）将"保留什么"与"当前给模型看什么"两个原本耦合的决策彻底分离：

- **它保留一切**——所有工具观测结果逐字存储在一个内容寻址、只追加（append-only）的外部存档库中；
- **它决定展示什么**——基于长度预算的确定性逻辑，但每次省略都会留下一个显式的、可解引用（dereferenceable）的指针。

恢复信息因此成为代理主动做出的决定，而非依赖检索器偶然命中。ARC不改变系统"保留什么"，只改变模型当前"看到什么"。

### 关键技术细节

1. **观测存储（Observation Store）**
   - 每个正常动作产生的观测结果 O 以稳定ID存储：`Hash(signature(A) || 0x1F || O)`，具体使用SHA1；可见ID取前8个十六进制字符，冲突时按4字符递增扩展。
   - 存储为只追加模式，任务生命周期内不删除、不覆盖。

2. **引用（Citation）**
   - 当压缩需要移除长观测时，ARC以紧凑的引用桩（citation stub）替代原文，形式为 `§id`，包含头部预览、尾部预览、元数据和 `_recall §id` 提示。
   - 短于阈值 ρ 的观测保持原样不放引用。

3. **召回动作（Recall Action）**
   - `_recall §id` 由代理框架在到达环境前拦截；有效ID将精确存储内容注入回转录中；无效ID返回最近匹配建议而非静默失败。
   - 附加 `_recall_meta §id` 只恢复元数据。
   - 有每次步数限制 r（默认2）、总物化召回预算和单次召回最大长度限制；超预算时按LRU将物化内容逐出为引用桩。

4. **确定性压缩例程（Compaction Routine）**
   - 不调用LLM，无额外模型调用或延迟。
   - 截断较旧的思考痕迹、保留短观测、将长观测替换为引用、最近轮次逐字保留；若仍超预算，则进一步将旧引用折叠为纯 `§id` 引用。
   - 证明的关键不变式：压缩后活动转录大小 K ≤ L，与已运行轮数无关；而所有观测仍原样保存在存档库中。

5. **触发机制**
   - 支持主动式（调用前预估长度）和反应式（溢出错误后触发）；评估中使用反应式路径。
   - 两种模式共享相同的确定性压缩例程与召回机制。

### 核心定理（Theorem 1，非正式表述）

若ARC满足：(i) 使用单射定宽出现标识符；(ii) 在压缩前逐字存储所有工具观测；(iii) 在外部内存保存完整引用目录而只在提示中物化有界页；(iv) 每次模型调用前强制活动视图预算 K ≤ L——则：每次模型输入至多 K 个token（与会话轮数无关）；任何具有有效ID的存档观测都可以精确返回，无需重新执行原动作；大观测通过 ⌈|O|/q⌉ 次不重叠分块精确重组。即ARC在系统层面**观测无损**，同时保持活动视图统一有界。

附录还证明了两项重要结论：所有引用同时可见与轮数无关的上下文界互不兼容；最坏情况下精确恢复任意历史必然需要线性增长的外部内存，而ARC的只追加存储一阶达到此下界。

## 六、主要结论与发现

1. **NIH精确召回优势显著**：ARC在Qwen3-8B上99.00%（最佳基线RAG 79.57%）、在Qwen3-32B上99.80%（最佳基线RAG 96.67%），平均99.40% vs 88.12%；几乎消除未作答现象（0.67/1000 vs 基线12–965）。
2. **LongBench推理任务仍有增益**：ARC在8B上27.47%（+1.64pp）、32B上32.47%（+1.80pp），平均29.97% vs 28.25%；未作答率显著降低（16.33和7.33 vs 基线23–74）。
3. **统计显著性**：所有配对比较均p < 0.05；与Full_context相比优势比无穷大；与最强基线相比优势比2.2–10.5。
4. **HBM效率大幅提升**：LongBench上带宽降低38.8%（8B）和73.5%（32B），较Sliding_window节省显著；NIH上节省80.3%（8B）和59.3%（32B），且**不牺牲任务成功率**——同时实现检索效果提升和成本下降，突破"准确率-延迟"权衡。
5. **全上下文（Full_context）不可靠**：即便32k窗口，NIH准确率仅2.93%，说明增大上下文窗口本身不能解决精确检索问题。
6. **跨平台稳健**：MI300X上ARC准确率99.57%/99.77%，与H200结果基本一致，验证方法不依赖厂商硬件特性。

- **核心贡献清晰**："无损压缩 + 显式寻址召回"的问题定义和方案设计极具针对性，切中现有方法的根本缺陷——无法可靠恢复被压缩的信息。
- **理论保障扎实**：附录提供了严格的定理证明（有界活动视图、精确无损、外部存储线性下界最优性），区分了机制级保证与端到端任务成功，学术态度严谨。
- **压缩过程零额外LLM调用**：确定性压缩例程不引入推理延迟，与LLM摘要形成鲜明对比。
- **效率与效果兼顾**：显著降低HBM流量和服务时间的同时提升任务成功率，实用价值突出。
- **实验方法论规范**：配对显著性检验、防自我怀疑护栏、跨平台验证、多维度消融，具备较强的可信度。

## 八、不足与局限

- **模型覆盖有限**：仅在Qwen3-8B和Qwen3-32B上验证，未涉及其它模型族（如Llama、GPT系）与更大的上下文窗口（如128k+），泛化性待检验。
- **LongBench增益较小**：推理类任务上优势收窄至1.6–2.3pp，说明大量失败来自推理错误而非召回失败；论文承认这一点是对ARC收益的下界估计。
- **小预算下ARC不具优势**：8k/4k召回预算时滑窗或摘要法反而领先，ARC需要最低召回预算才能发挥"记忆结构"作用。
- **引用token开销未量化**：每条引用含头部/尾部预览和提示，增加固定token开销，论文仅说明在补充材料中报告。
- **地址正确性非保证**：系统保证"有效地址→精确内容"，但不保证模型会选对地址；错误选择仍会导致失败。
- **对话历史类任务未解释**：论文提到隐式检索在对话历史任务上仍占优，但未在正文中展示细节，显式/隐式召回的确切互补机制尚待研究。
- **硬件成本数字潜在偏差**：HBM对比以"每个成功任务"归一化，在强制压缩调度下各方法成功数差异巨大（如ARC 989 vs 滑窗189），可能放大或缩小相对成本差距。
