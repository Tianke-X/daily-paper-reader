## 摘要
长上下文推理对于大型语言模型而言，由于注意力机制在文本令牌上的二次复杂度，计算成本仍然很高。视觉-文本压缩提供了一种有前景的替代方案，通过将文本渲染为图像，并使用视觉-语言模型进行处理，通常能减少令牌使用量。然而，现有方法无论查询相关性如何都应用统一压缩，可能在需要详细提取的场景中牺牲精度。我们提出了SEER，一个通过学习视觉扫描来选择与查询相关的图像，并仅在需要处检索文本内容的框架，结合了视觉压缩的效率和基于文本推理的精度。通过在工具交互轨迹上进行监督微调，SEER学会了自适应工具调用，以进行选择和检索。在长上下文基准上的实验表明，SEER通过选择性文本检索提高了提取精度，同时相对于全文本基线保留了平均提示令牌节省。在LongBench上，SEER实现了51.11%的平均准确率，比视觉-文本基线Glyph-9B高出2.33个百分点，比Qwen3-8B高出3.49个百分点。代码可在https://github.com/jiaweixu98/SEER获取。

## Abstract
Long-context reasoning remains computationally expensive for large language models due to the quadratic complexity of attention over text tokens. Visual-text compression offers a promising alternative by rendering text into images and processing them with vision-language models, often reducing token usage. However, existing approaches apply uniform compression regardless of query relevance, potentially sacrificing precision where detailed extraction is required. We present SEER, a framework that learns to select query-relevant images through visual scanning and retrieve textual content only where needed, combining the efficiency of visual compression with the precision of text-based reasoning. Through supervised fine-tuning on tool-interaction trajectories, SEER learns adaptive tool invocation for selection and retrieval. Experiments on long-context benchmarks show that SEER improves extraction precision through selective text retrieval while retaining average prompt-token savings relative to full-text baselines. On LongBench, SEER achieves 51.11% average accuracy, outperforming the visual-text baseline Glyph-9B by 2.33 points and Qwen3-8B by 3.49 points. Code can be accessed at https://github.com/jiaweixu98/SEER

# SEER：通过选择性视觉-文本压缩进行长上下文推理（论文总结）

## 1. 核心问题与整体含义（研究动机与背景）
- **背景**：长上下文推理（如多轮对话、长周期任务）对LLM日益重要，但自注意力机制对文本token呈二次复杂度，导致计算开销高昂。
- **既有方案**：视觉-文本压缩（如Glyph、Vist、DeepSeek-OCR）将长文本渲染成图像，用视觉-语言模型（VLM）处理，可实现3–4×的token压缩，并加快预填充。
- **关键缺陷**：现有视觉-文本压缩方法对全部上下文采用“统一压缩”，与查询（query）相关性无关。这种平局化处理会造成两难：过度压缩丢失细粒度细节，损害需要精确提取的任务；保守压缩则损失效率收益。
- **核心思路**：许多查询只依赖上下文中很小一部分的精确细节，其余内容仅用于全局理解。SEER提出“选择性压缩”——用视觉表示快速全局扫描定位相关区域，再对少数相关区域进行精确文本检索，从而兼顾视觉压缩的效率与文本推理的精度。

## 2. 方法论

### 2.1 核心思想与总体框架
- 采用 **Select-Retrieve-Reason（选择-检索-推理）** 三段式流程，将视觉选择与文本检索视为工具调用，集成到统一的推理轨迹中。
- 三个阶段的职责：
  1. **视觉选择（Visual Selection）**：模型基于全部渲染图像和查询，输出相关图像索引集合。
  2. **文本检索（Text Retrieval）**：根据所选索引，从渲染流程中保留的源文本中做确定性查找，返回对应文本。
  3. **推理（Reasoning）**：模型在同时保留全局视觉上下文和局部检索文本的条件下，生成链式推理与最终答案。

### 2.2 关键技术细节
- **文本渲染**：使用ReportLab和pdf2image，将文本渲染为A4页面图像（Verdana 9pt，72 DPI，20px边距），并保留每页源文本用于检索。
- **图像索引标记**：在每张图像前添加文本标记（如`[Image 1]`），使模型能引用具体图像编号。
- **工具调用格式**：模型输出结构化调用如`{"name": "select", "indices": [1, 3]}`，随后获取`<|observation|>`观测内容，再继续推理。这遵循ReAct风格的Thought-Action-Observation范式。
- **索引规范化**：预测的索引会去重、过滤出有效范围[1, m]，越界索引直接丢弃。
- **为何不用OCR而用直接检索**：
  1. 核心贡献在于学习“何时需要精确文本”，而非“如何提取文本”；
  2. 现实数字文档（PDF、网页、渲染代码）通常有源文本；
  3. 模块化设计允许未来无缝替换为OCR系统。

### 2.3 训练策略
- **初始化**：从Glyph-9B（基于GLM-4V架构）初始化，进行全参数监督微调（SFT）。
- **训练数据构造**：
  - 用Qwen3.5-9B对每页独立判断是否与查询相关（答案用于离线标注，不参与推理）；
  - 用Qwen3-32B在给定查询、文本上下文和选中页上下文的条件下生成CoT推理与答案；
  - 仅保留答案正确样本进行质量过滤；
  - 使用7个训练数据集（2WikiMQA、GovReport、HotpotQA、LCC-Python、MuSiQue、Qasper、TriviaQA），最终保留10,041条轨迹。
- **损失函数**：加权token级SFT目标，对模型生成部分（工具调用、推理、答案）设权重，对系统提供的观测token掩码为0。工具调用token加权2.0，格式标签加权1.2。公式如下：
  \[
  \mathcal{L}_{SFT} = \mathbb{E}_{(x,w)\sim\mathcal{D}} \left[ -\frac{\sum_{t=1}^{T-1} w_t \log p_\theta(x_{t+1}|x_{\le t})}{\sum_{t=1}^{T-1} w_t} \right]
  \]
  其中\(w_t\)为各token的权重。

### 2.4 推理流程（文字说明）
1. 输入渲染图像序列与查询；
2. 模型生成工具调用，选择若干图像索引；
3. 系统根据索引检索对应源文本，作为观测返回；
4. 模型在“全部视觉图像 + 检索文本”条件下生成`<think>`推理轨迹；
5. 模型输出最终答案。

- 评估指标按官方LongBench协议：QA用F1变体，摘要用ROUGE，分类用分类分数，检索用检索分数，代码用代码相似度；最终平均分按六个类别宏平均计算。

## 6. 主要结论与发现
- **主结果**：SEER在LongBench上达到51.11%平均准确率，较Glyph-9B（48.78%）提升2.33个百分点，较Qwen3-8B（47.62%）提升3.49个百分点（在作者报告设置下）。
- **提取密集型任务增益显著**：Qasper提升+8.75，NarrativeQA提升+4.22，HotpotQA提升+3.80，MultiFieldQA-Zh提升+19.17，MultiFieldQA-En提升+10.76。这些任务依赖数字、名称、日期等精确细节，文本检索优于视觉解码。
- **选择性行为**：SEER平均每查询仅选择1.59个有效图像（中位数1），且选择数饱和在3页以内，不随上下文长度扩展。
- **检索的作用**：端点消融显示，无检索（仅选择）平均准确率仅43.00%，而完整机制恢复至51.11%；中间检索预算k=1即可恢复约61.5%的端点增益，表明少量精确文本已足以修正大部分视觉误读。
- **选择器质量**：内部页面选择F1为0.578，优于随机（0.413）和首页（0.486），略低于BM25（0.606）；在低词法重叠样本上SEER更好，在BM25在高词法重叠样本上更优，二者互补。
- **效率权衡**：相比GLM全文本基线，SEER平均prompt压缩比仅1.28×（Glyph为3.14×），且以batch size 1在LongBench上测得的端到端延迟（中位数5.47秒）反而慢于全文本（1.07秒），原因是其显式输出推理轨迹。效率收益主要体现在prompt/KV缓存足迹与支持更长上下文，而非单请求延迟。
- **错误集中点**：多跳证据分布在多页的问题在单轮选择下容易失败，这是主要局限。

## 7. 优点
- **问题定义清晰**：指出统一压缩的固有精度-效率权衡，并引入查询相关性作为关键维度，切中现有方法盲点。
- **机制设计优雅**：将视觉“浏览”与文本“精读”互补，模拟人类阅读策略，直觉性强。
- **工具化集成**：把选择和检索建模为工具调用，天然适配现有ReAct范式，训练目标是完整的工具交互轨迹。
- **模块化与可替换性**：检索模块可替换为OCR，不依赖特定OCR能力，扩大了适用范围。
- **实验严谨性**：
  - 通过iso-training control排除“纯微调数据”的候选解释；
  - 通过k=0、k=1、k=all的检索预算分析量化了检索增益；
  - 对选择器质量做内在评估（页面级F1），避免仅用端到端下游分数掩盖选择器质量；
  - 与BM25、RLM等强替代方案直接比较，并如实报告BM25在词法任务上更优的情况。
- **坦诚披露局限性**：作者明确报告了延迟没有优势、部分任务prompt不降反增、选择器索引不可靠等问题，没有夸大压缩收益。

## 8. 不足与局限
- **效率声明范围窄**：token节省是平均值，7/21个任务上SEER的prompt比全文本基线更大；且效率优势定位于prompt/KV缓存足迹，而非实际推理延迟——单请求batch size 1下SEER延迟显著高于全文本基线（5.47s vs 1.07s）。
- **选择器稳健性差**：模型偶尔生成越界索引，当前实现直接丢弃而非修正，作为部署接口不够鲁棒。
- **增益高度依赖证据局部性**：当答案证据分散在超过3页时，单轮选择在构造上即存在召回上限。此外，训练数据的教师-过滤机制进一步减少了分布式证据样本，使这一局限内生于数据。
- **任务范围窄**：SEER只针对渲染后的长文档QA，未在自然图像、图表或OCR基准上评估，适用范围有限。
- **对比公平性局限**：SEER经过任务特定微调，而文本LLM基线是零样本直接推理，因此跨家族性能比较不能完全归因于方法本身；作者也承认这一点。
- **速度悖论**：虽然视觉压缩能减少token数，但在LongBench规模下视觉token的生成成本较高，预填充无优势，只有超长上下文（>128k文本token）或最大批处理场景下才体现速度收益。
