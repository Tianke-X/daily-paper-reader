## 摘要
长视界LLM代理会积累推理轨迹、操作和工具观测结果，这些内容最终可能超出模型的固定上下文窗口。现有压缩方法通过丢弃、总结或检索早期信息来解决这一限制，但可能会移除任务关键细节或无法可靠恢复它们。我们提出ARC（可寻址回忆压缩），一种将存档存储与活动上下文呈现分离的上下文管理框架。ARC将工具观测结果存储在仅追加、ID可寻址的日志中，并在需要压缩时用紧凑引用替换旧观测结果。代理随后可以使用这些标识符请求存储的内容，无需重新执行相应工具或仅依赖基于相似性的检索。我们使用Qwen3-8B（16k上下文窗口）和Qwen3-32B（32k上下文窗口）评估ARC。在Needle-in-a-Haystack评估中，ARC的平均精确答案准确率达到99.40%，而评估中最佳基线为88.12%。ARC还在我们的硬件成本模型下降低了估计的推理时间和HBM流量。在LongBench-v2 Hard子集上，ARC的平均准确率为29.97%，最佳基线为28.25%。这些结果表明，相对于评估的上下文管理基线，在测试设置下，明确的、基于地址的回忆可以提高信息保持和推理效率。

## Abstract
Long-horizon LLM agents accumulate reasoning traces, actions, and tool observations that can eventually exceed a model's fixed context window. Existing compaction methods address this limitation by discarding, summarizing, or retrieving earlier information, but they may remove task-critical details or fail to recover them reliably. We propose ARC (Addressable Recall Compaction), a context-management framework that separates archival storage from active-context presentation. ARC stores tool observations in an append-only, ID-addressable log and replaces older observations with compact citations when compaction is required. The agent can subsequently use these identifiers to request stored content without re-executing the corresponding tools or depending solely on similarity-based retrieval. We evaluate ARC using Qwen3-8B with a 16k context window and Qwen3-32B with a 32k context window. On the Needle-in-a-Haystack evaluation, ARC achieves an average exact-answer accuracy of 99.40%, compared with 88.12% for the best-performing baseline in our evaluation. ARC also reduces estimated serving time and HBM traffic under our hardware-cost model. On the LongBench-v2 Hard subset, ARC obtains an average accuracy of 29.97%, compared with 28.25% for the best-performing baseline. These results indicate that explicit, address-based recall can improve information retention and serving efficiency relative to the evaluated context-management baselines under the tested settings.

### 1. 核心问题与整体含义（研究动机和背景）

- **核心问题**：长视界（Long-horizon）LLM智能体在执行任务时，会不断累积推理轨迹、操作和工具执行的观察结果。由于LLM模型是“无状态”的，所有历史信息都必须拼接在单一、不断增长的对话记录（transcript）中。当这个记录超过模型的**固定上下文窗口（context-window limit）**时，系统会因“上下文溢出（context-window overflow）”而崩溃，导致任务无法继续。
- **现有方法及其缺陷**：目前的压缩方法包括：
  - **简单截断**：直接丢弃最早的信息，可能导致关键细节永久丢失。
  - **分层摘要**：使用LLM生成历史摘要，但摘要本身是有损的，无法恢复被省略或改写的细节。
  - **结构化状态**：将历史压缩成固定格式的对象（如JSON），但任何未被模型化的信息都会被丢弃。
  - **检索增强生成（RAG）**：将历史存储在外部向量数据库，通过语义相似性检索。但恢复是隐式的，依赖于检索质量，无法保证精确恢复特定信息。
- **研究动机**：所有现有策略本质上都是 **有损的**。一旦历史被修剪、改写或向量化，就无法保证精确恢复。论文旨在探索压缩是否可以做到 **严格无损**，同时保持活动提示词（active prompt）的边界可控。

### 2. 论文提出的方法论

- **核心思想**：将“**保存什么**”（archival storage）与“**显示什么**”（active-context presentation）两个决策分离。ARC保证**保存一切**在可寻址的存储中，而活动上下文中只展示长度有限的摘要和最新信息，所有被省略的内容都留下一个**显式的、可解引用的指针（citation）**。

- **关键技术细节**：
  - **可寻址存储（Addressable Store）**：一个仅追加的、不可删除的日志。每次工具执行产生的观察结果`O`，都会用一个`ID`（基于其内容和动作签名的SHA1哈希）永久存储。
  - **引用（Citation）**：当压缩发生时，长的观察结果会被替换为一个紧凑的引用（如`§a91f3c20`），包含预览和元数据，但不包含完整内容。代理可通过`_recall §id`动作显式请求恢复完整内容。
  - **确定性压缩（Deterministic Summarization）**：压缩过程不调用LLM，而是通过截断、引用等规则生成一个长度确定的摘要，降低了延迟和成本。
  - **精确块式召回（Exact Chunked Recall）**：当召回一个非常大的观察结果时，ARC会分块返回，每块不超过`q`个token，确保完整内容可以被重建，而非简单截断头尾。
  - **活动视图预算**：为任务前缀、摘要、最近的轮次、引索页面和召回的缓冲内容分配固定的Token预算，确保模型输入始终小于上下文窗口限制。

- **算法流程**：
  1.  **初始化**：创建空的观察存储和引号集，定义任务的系统提示和最终目标。
  2.  **循环**：模型根据当前对话记录生成想法和动作。
  3.  **执行**：框架执行动作，产生观察结果。
  4.  **存储**：观察结果及其ID被存入仅追加的观察存储。
  5.  **上下文窗口检查**：如果产生的对话记录超过上下文窗口限制，则触发压缩。
  6.  **压缩**：运行确定性压缩程序，用引用替换较老的、长的观察结果，保证新的对话记录在预算内。
  7.  **代理交互**：代理在后续轮次中可以发出`_recall §id`命令，系统会从存储中取出完整内容注入回对话记录。召回也有预算限制，LRU（最近最少使用）策略会从对话记录中移除旧的召回内容，恢复为引用格式。

### 8. 不足与局限

- **在复杂推理任务上的优势相对有限**：在LongBench-v2上，ARC的优势（约+1.7%）相比NIH（+11%）要小得多。论文解释这是因为LongBench还需要更强的推理能力，而ARC只保证了信息的可获取性。这意味着，如果模型本身的推理能力是瓶颈，ARC的收益会受限制。
- **依赖模型发起的正确召回**：ARC的保证是机制层面的。它确保了在给定有效地址的情况下可以精确恢复，但并不保证语言模型会自动选择正确的地址或发出足够的recall命令。端到端的任务成功仍然依赖于模型自身的决策能力。
- **确定性摘要的局限性**：ARC的摘要部分通过确定性规则（如截断长观察、引用）生成，可能无法像LLM生成的摘要那样保持高级别的语义连贯性或上下文关系，可能会丢失隐藏在推理轨迹中的“软”信息。
- **需要最小召回预算**：在LongBench的消融实验中，当召回预算过小（8k/4k）时，ARC表现不如某些基线（如Sliding_window）。这表明ARC需要一个最低限度的“工作空间”来发挥其优势。
- **额外的Token开销**：每个ARC的引用（head/tail preview, recall hint）都会引入固定大小的额外Token开销，相比于直接丢弃观察，这会稍微压缩可用上下文预算。
- **模型与任务的选择偏差**：所有实验均基于Qwen3模型家族。其推广性到其他LLM、分词器或特定的推理风格还有待验证。
