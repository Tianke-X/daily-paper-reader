## 摘要
多轮信息寻求对话需要跨轮次的多跳推理和长距离依赖追踪。然而，现有的RAG系统通常将对话记忆表示为原始对话历史、重写查询或非结构化摘要，这使得难以恢复后续查询所需的特定先前推理步骤和证据。我们的关键洞察是通过将对话上下文表示为子问题级别的推理痕迹，从而使对话记忆与检索对齐。基于这一洞察，我们引入了MuMu-QA，一个带有显式跨轮次子问题依赖注释的多轮多跳RAG基准，以及CMT-RAG，一个用于该设置的互补记忆框架。在每一轮中，CMT-RAG采用一个状态空间轨迹生成器，其循环状态作为运行时记忆，以整合最近的对话上下文并将当前查询分解为结构化的轨迹草稿，其中包含面向检索的子问题和对先前轨迹的依赖。然后，它用检索到的证据为这些草稿提供依据，并将它们作为持久记忆痕迹存储在会话级DAG中，使未来轮次能够高效地恢复相关的先前推理和证据。在MuMu-QA和语料级RAG基准上的实验表明，CMT-RAG在答案准确率上始终优于五类RAG基线。

## Abstract
Multi-turn information-seeking conversations require both multi-hop reasoning and long-range dependency tracking across turns. However, existing RAG systems typically represent conversational memory as raw dialogue history, rewritten queries, or unstructured summaries, making it difficult to recover the specific prior reasoning steps and evidence required for follow-up queries. Our key insight is to align conversational memory with retrieval by representing dialogue context as sub-question-level reasoning traces. Building on this insight, we introduce MuMu-QA, a benchmark for multi-turn multi-hop RAG with explicit cross-turn sub-question dependency annotations, and CMT-RAG, a complementary memory framework for this setting. At each turn, CMT-RAG employs a state-space trace generator, whose recurrent state serves as runtime memory, to incorporate recent conversational context and decompose the current query into structured trace drafts containing retrieval-oriented sub-questions and dependencies on earlier traces. It then grounds these drafts with retrieved evidence and stores them as persistent memory traces in a session-level DAG, enabling future turns to efficiently recover relevant prior reasoning and evidence. Experiments on MuMu-QA and corpus-level RAG benchmarks show that CMT-RAG consistently outperforms five categories of RAG baselines in answer accuracy.

## 2. 方法论（核心思想、关键技术细节、算法流程）

### 核心思想
将对话中的每个用户查询分解为结构化的子问题（sub-question），每个子问题对应一个 trace。trace 包含：子问题文本、用于 DAG 查找的关键词（keyword）、依赖的前驱 trace 集合、以及直接检索到的证据段落标识。所有 trace 构成一个有向无环图（DAG），持久化全对话记忆。同时，一个轻量级状态空间模型（SSM，基于 Mamba-2）维护循环状态，作为运行时记忆，承载局部 discourse 连续性（如话题焦点、意图转移、共指）。

### 关键技术细节
1. **状态空间 trace 生成器（State-Space Trace Generator）**：
   - 基于 Mamba-2 的 SSM 骨干，其选择性状态空间混频器（selective state-space mixer）维护跨轮次的循环隐藏状态 `h_{t-1}`。
   - 在每轮 `t`，输入当前查询 `q_t` 和前一状态 `h_{t-1}`，输出一组结构化 trace 草稿 `{T_draft_k}_k` 和更新状态 `h_t`。
   - 每个草稿格式为：`T_draft_k = (q_decom_k, kw_k, deps(k))`，其中 `q_decom_k` 是分解出的子问题，`kw_k` 是用于 DAG 轻量级词法匹配的关键词，`deps(k)` 是依赖的前驱 trace 标识符列表。
   - 通过 Low-Rank Adaptation (LoRA) 微调和 Direct Preference Optimization (DPO) 进行训练。
2. **持久化 trace DAG**：
   - 每个完成 trace 被附加到会话级 DAG，包含解析后的子问题、关键词、依赖边、本地检索到的段落标识。
   - 未来轮次时，通过依赖边直接获取前驱 trace 的答案（用于参数替换），通过关键词匹配获取历史 trace 存储的证据段落。
3. **训练方法**：
   - **三阶段课程学习 SFT**：Stage 1 单轮示例学习 trace 语法；Stage 2 短多轮对话；Stage 3 长多轮对话，并保留早期示例回放。
   - **DPO 优化**：从长对话模型中采样多个候选 trace，通过固定检索-读取器流水线执行，使用复合奖励 `R = F_final + γ * F_sub`（γ=0.2）排序，构造偏好对更新生成器。

### 算法流程（以单轮推理为例，见 Algorithm 1）
1. 使用 SSM 生成器根据当前查询和前一隐藏状态产生 trace 草稿集合。
2. 对每个草稿按拓扑顺序处理：
   - 通过依赖边进行答案引用解析（RefRes），得到解析后的子问题 `q_sub_k`。
   - 通过关键词在 DAG 中查找历史 trace（Index），获得相关证据段落标识。
   - 直接对 `q_sub_k` 进行新鲜检索（Top-5），获得本地段落标识。
   - 合并历史与本地证据，送入**无状态读取器**（如 Qwen3-32B）生成子答案。
   - 完成 trace 并追加到 DAG。
3. 所有子问题处理完毕后，调用聚合读取器生成轮次最终答案。

## 6. 主要结论与发现

1. **CMT-RAG 在所有对比中取得最佳答案准确率**：在 MuMu-QA long-dialogue 上，EM/F1 分别达到 41.73/55.63（Qwen3-32B）和 44.70/57.55（Llama-3.3-70B），显著超越最强基线（如 Direct C-RAG、ConvSearch-R1 等）。
2. **两个互补记忆通道各有侧重**：
   - SSM 循环状态在**所有长度区间**都对最终 F1 贡献最大（移除后 F1 下降 7–11 点）。
   - 持久 DAG 的效益随对话长度增加而增大（在超长对话中贡献约 1.15 F1 点）。
3. **SSM 骨干优于 Transformer**：SSM（Mamba-2）不仅 F1 稍高（+1.60），且端到端延迟降低 48.4%（0.83s vs 1.61s/turn），原因是 SSM 状态增量处理而 Transformer 需要重编码完整历史。
4. **跨基准迁移能力强**：在多轮 RECOR 上全指标最优；在单轮 HotpotQA 上取得最佳 EM，在 2WikiMultiHopQA 上仅次于 LogicRAG 但效率高出 8 倍。
5. **记忆框架本身已提升性能**：即使使用读者自身生成 trace（无专门生成器），引入 CMT 框架也带来 2.66–3.78 F1 点增益（表 2）。

## 7. 优点

- **方法论创新**：首次将对话记忆显式表示为子问题级别的推理痕迹（trace），并将记忆单元与检索单元统一，解决了现有方法中记忆粒度与检索需求的错配。
- **架构设计简洁有效**：通过轻量 SSM 状态处理局部上下文 + 持久 DAG 处理远距离依赖，使读者保持无状态，降低了读者复杂度，支持长对话高效推理。
- **新基准贡献**：MuMu-QA 提供细粒度跨轮次子问题依赖标注，填补了现有多轮 RAG 基准缺乏这种监督的空白，具有较高研究价值。
- **实验全面且严谨**：消融实验覆盖框架、生成器、记忆通道、骨干、超参数等；对比方法覆盖五大类、14+ 系统；评价指标同时包含答案质量和上下文效率。
- **可迁移性验证**：在三个额外语料级基准上验证，证明方法不限于合成数据，具备泛化能力。
- **DAG 设计细节**：分离关键词（用于轻量词法匹配）和子问题（用于稠密检索），有效降低依赖查找开销又不牺牲性能。

## 8. 不足与局限

- **数据偏差**：MuMu-QA 完全从 MuSiQue 合成，其推理模式、实体分布、领域覆盖均继承 MuSiQue（主要维基百科事实类 QA），可能无法代表真实人类的多轮对话（如闲聊、任务型对话）。作者也承认需要评估人类撰写对话。
- **对子问题分解的依赖**：CMT-RAG 依赖准确的子问题分解和依赖预测。如果生成器产生错误分解或遗漏必要依赖，可能导致检索不正确或答案错误。虽然 DPO 部分缓解，但仍不完美（Oracle trace 给出 3.27 F1 点提升空间）。
- **超长对话外推能力有限**：训练仅覆盖短和长（最大 32 轮），超长（33–67 轮）上表现下降（图 4 中 w/o SSM 状态条件下 F1 从 50.10 降至 48.95），说明 SSM 状态对长度的泛化有待加强。
- **未讨论多任务兼容性**：DPO 训练针对特定读者（Qwen3-32B 或 Llama-70B），切换读者需重新生成偏好对并训练，可能增加部署成本。
- **缺少与端到端多轮训练方法的比较**：未对比基于强化学习端到端优化的多轮 RAG 方法（如某些 Agent 框架），虽然文中对比了 ReAct、Self-Ask 等，但这些是经典代理，并非专为多轮优化。
- **计算开销**：虽然 SSM 生成器轻量，但每轮仍需要使用 DAG 查找和多次检索调用（每个子问题一次+历史检索），端到端延迟为 0.83s（Qwen）+ 检索时间，对于实时对话可能仍有压力。
