## 摘要
智能体记忆工作负载混合了直接事实查询、关系链与当前状态推理，以及基于长历史的广泛综合。我们描述了超认知模式（SCM），一种将显式或自动选择的每查询模式映射到共享摄入基板上的检索与综合负载的架构。一个冻结的语义分类器和运行时门控将查询调度到融合词汇与稠密检索、图或迭代多跳处理，以及分层长形式综合中。基板结合了多粒度嵌入、提取的三元组、事实版本元数据以及可选的异步丰富。我们在三个基准上对部署配置进行了表征：长期对话记忆（LoCoMo；n=1,986）、MemoryAgentBench（MAB；n=3,671）和LongMemEval（n=500）。参考运行在LoCoMo事实类类别上记录为84.87%，对抗性弃权为68.61%，在两次重复中MAB为61.49%，LongMemEval为86.00%。基于存储库的复现产生了类似的聚合得分，并支持任务和模式条件的失败分析。原始基线输出、LoCoMo和LongMemEval的对齐端到端时序以及完整的令牌分类账不可用；存储的行也省略了一些最终运行时决策。结果描述了一种实现的路由配置及其诊断失败模式，而源码检查验证了每查询控制接口和共享基板设计。因果路由效应、效率提升和统计显著性仍超出可用证据范围。

## Abstract
Agent-memory workloads mix direct factual lookup, relation-chain and current-state reasoning, and broad synthesis over long histories. We describe Supra Cognitive Modes (SCM), an architecture that maps explicit or automatically selected per-query modes to retrieval and synthesis payloads over one shared ingest substrate. A frozen semantic classifier and runtime gates dispatch queries among fused lexical and dense lookup, graph or iterative multi-hop handling, and stratified long-form synthesis. The substrate combines multi-granularity embeddings, extracted triples, fact-version metadata, and optional asynchronous enrichments. We characterize the deployed configuration on three benchmarks: Long-term Conversational Memory (LoCoMo; n = 1,986), MemoryAgentBench (MAB; n = 3,671), and LongMemEval (n = 500). The reference run records 84.87% on LoCoMo factoid categories and 68.61% on adversarial abstention, 61.49% on MAB across two repetitions, and 86.00% on LongMemEval. A repository-backed reproduction produces similar aggregate scores and supports task- and mode-conditioned failure analysis. Raw baseline outputs, aligned end-to-end timing for LoCoMo and LongMemEval, and complete token ledgers are unavailable; stored rows also omit some final runtime decisions. The results characterize one implemented routed configuration and its diagnostic failure patterns, while source inspection verifies the per-query control interface and shared-substrate design. Causal routing effects, efficiency gains, and statistical significance remain outside the available evidence.

## 2. 论文提出的方法论：核心思想、关键技术细节、算法流程

### 2.1 核心思想

- **模式-负载-过程（mode–payload–procedure）接口**：
  - **模式（mode）**：语义标签，由应用显式传递或自动分类器产生（4种：单事实查找、长形式综合、时间锚定查找、最新版本解析）。
  - **负载（payload）**：由模式映射得到的检索与综合配置（如检索深度、是否启用图遍历等）。
  - **过程（procedure）**：具体执行查询的代码路径（直接查找、图/迭代多跳处理、分层长形式综合）。
- **运行时间门控（runtime gates）**：可以根据查询特征或已检索上下文修改初始负载，例如检测到多跳标记时强制切换为多跳处理，或发现检索结果包含示例时路由到“范例上下文”模式。
- **共享异步入教基板（shared asynchronous ingest substrate）**：所有过程都读取同一基板，该基板包含多粒度嵌入、提取的三元组、事实版本元数据以及可选的异步缓存增强信号（如文档形状、关键点、规范实体等）。摄入分两层：Tier-1强制写入，Tier-2可选异步增强。

### 2.2 关键技术细节

- **冻结语义分类器**：使用Claude Haiku 4.5，温度0，在1065个合成问题形状示例上选出（整体96.06%，宏平均95.80%），并在568个共识标签的真实开发集上验证（微平均90.14%，宏平均89.37%）。分类器输出无法解析时默认使用单事实查找。
- **直接查找过程（Direct Lookup）**：
  - 查询嵌入，可选添加两个轻量释义。
  - 并行运行Okapi BM25（k1=1.5, b=0.75）及稠密检索（块、句、段落级别）。
  - 使用倒数秩融合（RRF, k=30）合并候选，最终深度限制100块。
  - 单次Sonnet调用生成答案，指令要求在实体不支持时输出“No information available”。
- **图与迭代多跳过程（Graph / Iterative Multi-hop）**：
  - 从基板读取三元组（包含规范化主语、谓语、客体、来源记忆、置信度、版本号、活动状态及时间字段）。
  - 规划器选择种子实体和跳序列（有限谓词词汇表）；接地行走器选择实际出入边。
  - 候选三元组按版本号降序排列（当前状态查询优先使用新值）。
  - 若图规划失败，可回退到迭代稠密检索或标准融合检索。
- **长形式综合过程（Long-form Synthesis）**：
  - 按时间顺序采样语料，目标200块。
  - 应用多轮“子弹-展开”过程（bullets-expand）。
  - 使用已缓存或在线语料形状分类器（叙事、研究、技术、日志、混合）选择覆盖规划和展开提示。

## 6. 主要结论与发现

- SCM在三个基准上均取得最高的聚合准确率：
  - LoCoMo事实类84.87%，对抗性弃权68.61%，混合全集81.22%。
  - MAB平均61.49%（两次运行61.72%和61.26%）。
  - LongMemEval 86.00%。
- 本地复现与参考运行在主要指标上相差约1个百分点，提供了一致性证据。
- 失败模式分析揭示薄弱环节：
  - MAB中电影推荐（Movie-Rec 179/200失败）、长程摘要（InfBench-Sum F1仅32.77%）、多跳事实整合（FC-MH 229/400失败）是主要错误源。
  - LongMemEval中时序推理（25/133失败）和多会话（26/133）错误集中在检索后综合阶段。
  - LoCoMo弃权中许多失败是“接近正确”的拒绝或语义合理修正但未命中词汇目标。
- 分类器在合成和真实开发集上表现良好（>89%宏平均），但缺乏路由效率的端到端测量。

## 7. 优点

- **新颖的控制接口**：将每查询操作点显式暴露，从“固定策略”转向“查询感知路由”，且模式、负载、过程分离，提高了灵活性。
- **共享基板设计**：所有过程读取同一基板，避免了数据冗余；Tier-1强制写入确保查询就绪，Tier-2可选增强避免阻塞。
- **诊断能力**：保留模式标签、检索块和得分结果，支持可复现的模式条件失败分析。
- **透明度**：提供了完整的分类器开发证据、配置映射、运行参数，并明确标注了所有证据边界（如基线不可得、时序不对齐、不统计显著）。
- **工程落地特征**：包含运行时门控（如多跳检测、ICL路由、空检索回退等）和错误修正（如枚举索引导致的21.8%错误在修正后变为88.2%）。

## 8. 不足与局限

### 8.1 实验覆盖不足

- 缺少**固定策略控制**（如始终使用直接查找 vs. 始终使用图多跳），无法确定路由是否真正带来增益。
- 大多数单元为**单次运行**，除MAB外无方差估计。
- **时序不对齐**：只有MAB的得分答案与记录延时对齐，LoCoMo和LongMemEval的离线综合阶段时长未记录。
- **成本无法精确对比**：缺少API计费凭证和令牌使用记录，无法进行精细成本分析。
- **判分者验证不足**：未进行人工判分一致性研究，所有LLM判分结果仅表示与基准判分者的一致度。
- **向量存储不同**：SCM使用pgvector，Mem0使用ChromaDB，可能引入不可控变量。

### 8.2 偏差风险

- **数据污染**：三个基准可能出现在预训练数据中，影响绝对分数和相对差异。
- **判分者提示轮询**：LoCoMo判分者提示来自一方比较系统，可能引入循环性问题，尽管所有输出使用相同提示标准化了打分。
- **分类器仅基于合成数据**：最新版本解析模式在真实开发集上几乎无样本，泛化能力未知。

### 8.3 应用限制

- SCM的路由配置是针对特定基准调优的，通用性和稳定性未验证。
- 系统对模型提供商（OpenAI、Anthropic）和商业API有强依赖，更换模型可能改变结果。
- 实时场景中，路由决策的额外延迟和成本需要权衡；论文未提供与固定策略的延迟或成本对比。

### 8.4 论文自身声明

论文在多个位置明确限定了证据范围：
- “Causal routing effects, efficiency gains, and statistical significance remain outside the available evidence.”
- “The results characterize one implemented routed configuration and its diagnostic failure patterns… not a comparison of automatic routing against a fixed policy.”
- “We report descriptive percentages and percentage-point differences. We do not report p-values, confidence intervals, or claims of statistical significance.”
